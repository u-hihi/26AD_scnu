## 1. 배경·목적

### 1.1 배경

- 순천대학교 학생은 수업 사이에 애매하게 빈 시간이 자주 생깁니다. 이 시간을 **공강**이라고 부릅니다.
- 공강에 공부하거나 쉴 곳으로 빈 강의실을 쓰고 싶어도, 어느 강의실이 비어 있는지 알기 어렵습니다.
- 지금은 건물을 돌아다니며 문을 열어 보거나, 시간표를 직접 뒤져 봐야 합니다.
- 학교 공식 시간표는 학기마다 공지사항에 HWP(한글 문서) 파일로 올라옵니다. 따로 "실시간 조회" 페이지(향림통시스템)도 있습니다.
- 하지만 이 자료들은 "지금 어느 강의실이 비었는지"를 한눈에 보여 주지 않습니다.

### 1.2 목적

- 서비스 이름은 **"순천대 공실 알리미"**(가칭: 임시로 정한 이름)입니다.
- 학생이 웹 브라우저(PC·휴대폰)로 **지금 비어 있는 강의실을 바로 찾게** 합니다.
- 원하는 날짜·교시를 골라, 건물마다 빈 강의실을 미리 볼 수 있게 합니다.
- 강의실의 수용 인원·다음 수업 시각을 함께 보여 줘서, 얼마나 오래 쓸 수 있는지 판단하게 돕습니다.

### 1.3 성공의 모습 (정성 목표)

- 학생은 **앞 수업이 끝난 건물이나 다음 수업이 있는 건물**을 기준으로 빈 강의실을 찾습니다. 멀리 이동하지 않고 그 건물 안에서 고르는 것이 보통입니다.
- 그래서 학생이 **날짜·교시 고르기 → 캠퍼스맵에서 건물 → 층별 안내도에서 공실** 순서로 헤매지 않고 찾을 수 있어야 합니다. 캠퍼스맵은 위에서 내려다본 지도 모양이며, 끌어 옮기고 확대해 건물을 누릅니다. 건물을 누르면 층별 안내도가 나오고, 층마다 고른 날짜·교시의 공실 / 수업중이 보입니다(안내도 모양은 7.5 참고).
- 학생이 앱을 설치하지 않고 웹 브라우저로 쓸 수 있습니다. **PC 화면을 기준**으로 만들되, 휴대폰 브라우저로 열어도 깨지지 않습니다.
- 사용자가 화면에서 "이 정보가 언제 기준인지"를 항상 알 수 있습니다.
- 숫자로 된 목표(화면이 뜨는 시간 등)는 `03_기능명세서.md`의 NFR·SLO(비기능 요구·목표 수준)에 **제안값**으로 적었습니다. 사용자가 확인한 뒤 확정합니다.

## 2. 대상·사용자

| 구분 | 누구 | 하는 일 | 주로 쓰는 곳 |
|---|---|---|---|
| 학생 사용자 | 순천대학교 학생 | 날짜·교시 고르기, 건물·층별 공실 보기, 강의실 상세 보기, 공지 보기, 문의·신고 보내기 | 사용자 화면(웹) |
| 관리자 | **1명(사용자 본인, 이 서비스를 만드는 사람)**. 더 필요하면 나중에 추가합니다. | 시간표·폐강 교과목 파일 반영, 학기·건물·층·강의실·캠퍼스맵·공휴일 정보 관리, 공지·배너·팝업 관리, 문의·신고 처리, 방문 통계 보기 | 사이트 밖의 도구: 관리자 PC 변환 도구, 구글 시트, 구글폼 응답 시트, 구글 애널리틱스 |

- 이번에는 **PC 웹을 먼저** 만듭니다. 다만 공강에 이동하면서 휴대폰으로 열 수도 있으므로, 휴대폰 브라우저에서도 화면이 깨지지 않게 합니다(반응형).
- 서비스는 **정적 사이트**입니다(4장 참고). 자체 서버가 없습니다.
- **학생 로그인은 넣지 않습니다.** 나중에 학교 공식 앱과 연동하거나 공식 앱에 편입될 수 있어, 계정 기능은 그때 학교 계정에 맞추는 편이 낫습니다.
- **사이트 안에 관리자 화면과 관리자 로그인도 두지 않습니다.** 관리 일은 사이트 밖의 무료 외부 도구와 파일 수정으로 합니다.
- **사이트는 학생 정보를 저장하지 않습니다.** 학생 정보는 **문의할 때 이메일만** 받습니다(선택 입력·동의). 이 이메일은 처리 후 지웁니다(7.7).
- 구글 애널리틱스가 쓰는 식별값(쿠키: 브라우저에 남기는 작은 기록)을 어떻게 안내하고 동의받을지는 `09_보안_개인정보.md`에서 정합니다.
- 예상 사용자는 **약 7,000명**입니다. 모두가 한꺼번에 접속하지는 않을 것으로 봅니다(동시 접속은 적음).

### 2.1 대표 사용 장면

1. 2교시 수업이 공과대학 1호관에서 끝났고, 4교시까지 1시간이 빕니다. 학생이 서비스를 열면 오늘 날짜·지금 교시가 이미 골라져 있습니다. 캠퍼스맵을 끌고 확대해 **공과대학 1호관(D2)을 누르면** 층별 안내도가 나옵니다. 층을 스크롤하다 보니 3층에 공실이 있습니다(예시 장면).
2. 학생이 한 강의실을 누르면 "약 30명(추정) · 다음 수업 13:00 시작"이 보입니다.
3. 내일 오후 조별 모임 장소를 찾으려고, 필터 달력에서 **내일 날짜**를 고르고 그 밑에서 **5교시**를 고른 뒤 공과대학 1호관을 누릅니다.

### 3.1 이번에 할 것

**학생이 쓰는 기능**

| 임시 번호 | 기능 | 쉬운 설명 | 03 FR |
|---|---|---|---|
| 기능 1 | 캠퍼스맵에서 건물 고르기 | 캠퍼스맵을 **위에서 내려다본 지도 모양**으로 보여 주고, **끌어서 옮기고 확대·축소**하며 건물을 눌러 고릅니다. 캠퍼스맵 대신 건물 목록에서 고를 수도 있습니다. 건물은 하나만 고릅니다. | FR-001, FR-002 |

| 기능 5 | 초기화 버튼 | 누르면 필터(날짜·교시)가 **오늘 날짜·지금 교시**로 초기화되고, **캠퍼스맵 첫 화면**으로 돌아갑니다. 고른 건물·층별 안내도는 닫힙니다. 자동 새로고침은 없습니다. | FR-006 |
| 기능 6 | 공지사항·배너·팝업 보기 | 관리자가 구글 시트에 적은 공지사항·배너·팝업을 사이트가 읽어 와서 보여 줍니다. | FR-007, FR-008, FR-009 |

> `idea.md`의 기능 "지금 빈 강의실 목록"은 기능 1·2·3(날짜·교시 → 캠퍼스맵 → 건물 → 층 → 공실)으로 구체화했습니다.

이 기능들을 돌리기 위해 함께 필요한 것:

- **정적 사이트**: 미리 만든 화면 파일과 데이터 파일만 보여 주는 사이트로 만듭니다. 자체 서버가 없습니다. 사이트를 올려 둘 호스팅 서비스는 관리자 구글 계정으로 쓸 수 있는 서비스를 먼저 고릅니다. 예: Firebase Hosting(구글이 제공하는 사이트 올리기 서비스). 확정은 `08_아키텍처_ADR.md`에서 정합니다.
- **관리자 기능(사이트 밖에서 외부 도구·파일로 함)**: `03_기능명세서.md`에서 "관리자 기능"으로 따로 번호를 붙입니다.
  - 대시보드: 일일 방문자 수·건물 조회수는 구글 애널리틱스로, 처리할 일(문의·신고)은 구글폼 응답 시트로 봅니다. (FR-019)
  - 콘텐츠 관리: 공지사항·배너·팝업을 구글 시트(공지용)에서 등록·수정·삭제합니다. 이 시트에는 공휴일을 적는 탭도 함께 둡니다. (FR-020)
  - 고객 대응: 1:1 문의와 신고를 구글폼으로 받아 구글 시트에서 처리합니다. 문의 답변은 이메일로 보냅니다. 신고에는 답장하지 않고 처리만 합니다. (FR-021)
  - 관리자 계정·보안: 관리에 쓰는 계정을 **관리자 구글 계정 하나**로 합칩니다(구글폼·구글 시트·구글 애널리틱스·호스팅). 이 계정에는 2단계 인증을 권장합니다. (FR-022)
  - 학기 정보 입력: 학기 이름·시작일·종료일을 파일에 적습니다. (FR-023)
  - 시간표 파일 반영: 학교 HWP 시간표를 우리 양식(엑셀/CSV: 표 형식 파일)으로 옮겨 **관리자 PC 변환 도구**에 넣습니다. 도구가 검사한 뒤 사이트용 데이터 파일을 만들고, 관리자가 사이트를 다시 올립니다. (FR-024)
  - 폐강 교과목 파일 반영: 학교가 주는 **최종 폐강 교과목 파일**(xlsx: 엑셀 파일)을 변환 도구에 넣습니다. (FR-025)
  - 새 학기 반영 시 지난 학기 수업 시간 데이터 지우기 (FR-026)
  - 강의실·층·수용 인원 자동 정리, 건물·층·강의실 정보 관리, 캠퍼스맵 관리(건물 영역 설정·캠퍼스맵 그림 교체) (FR-027~FR-029)
  - 공휴일 목록 관리: 공지용 구글 시트의 "공휴일" 탭에 매년 한 번 그해 공휴일을 적고, 임시공휴일·학교 휴업일이 생기면 추가합니다. 사이트를 다시 올리지 않아도 반영됩니다(7.6). (FR-030)
- **웹(PC 우선)**: 브라우저에서 쓰는 웹 화면입니다. 설치하는 앱이 아닙니다. PC 화면을 기준으로 하고, 휴대폰 브라우저에서도 열립니다.

### 3.2 이번에 안 할 것 (범위 밖)

- 학교 공식 앱과 연동하거나, 공식 앱에 기능을 추가하는 것 (나중에 연동·편입 가능성은 열어 둠)
- 휴대폰 전용 화면(모바일 버전)과 안드로이드·iOS(아이폰 운영체제) 앱 (웹을 먼저 만든 뒤 검토)
- 학생 로그인·계정 기능 (공식 앱 연동 시 학교 계정에 맞춰 검토)
- **사이트 안의 관리자 화면·관리자 로그인** (관리는 사이트 밖의 외부 도구와 파일 수정으로 함)
- **자동 새로고침** (화면을 켜 둔 채 교시가 바뀌어도 자동으로 바꾸지 않음. 학생이 초기화 버튼을 누름)
- **접근성 기능**(키보드만으로 조작하기 등) (나중에 추가. 지금은 마우스 조작으로 충분하다고 봄)
- 교시 범위 검색(예: 3~5교시)과 "전체 건물" 검색 (교시는 하나만, 건물도 하나만 고름)
- 주말·공휴일 운영 (달력에서 주말·공휴일 날짜는 고를 수 없음. 오늘이 주말·공휴일이면 건물을 누를 때 "운영하지 않는 날입니다" 같은 문구만 보여 줌)
- 학사 시스템과의 자동 연동 (학교 승인 필요, 다음 단계 후보)
- 공개 시간표 페이지 자동 수집(크롤링: 프로그램이 웹 페이지 내용을 자동으로 긁어 오는 것) (학교 허락 필요, 다음 단계 후보)
- 휴강·보강·시험 일정 (알 수 없어 반영하지 않음. 특히 휴강은 예고 없이 생김)
- 10교시·야간 수업 시간대(18:00 이후) (지원하지 않음)
- 외부 지도 서비스(카카오맵 등)·GPS(위성으로 현재 위치를 알아내는 기능) 현재 위치 표시 (캠퍼스맵을 따로 준비해 쓰므로 제외)
- 외부 공휴일 서비스(API: 프로그램끼리 데이터를 주고받는 창구) 연결 (정적 사이트에서는 인증키가 드러나므로 쓰지 않음. 공휴일은 관리자가 구글 시트에 직접 적음, 7.6)
- 강의실 콘센트 정보
- 알림(웹 푸시: 브라우저를 통해 PC·휴대폰에 알림을 보내는 기능)·즐겨찾기·공강 시간 입력 (수업은 매주 같은 시간·같은 장소에서 열려 알림의 필요성이 낮으므로 제외)

## 5. 시스템 구성 개요

서비스는 **정적 사이트 + 무료 외부 도구**로 이루어집니다. 자체 서버는 없습니다. 사이트 안에는 학생 화면만 있고, 관리 일은 모두 사이트 밖에서 합니다.

아래 구성은 학생들에게 공개한 뒤의 모습입니다. 공개 전에는 관리자가 로컬 PC(관리자 본인의 컴퓨터)에서 사이트를 실행해 확인합니다(7.7).

```
[학생 PC·휴대폰] 사용자 화면(정적 사이트)
   |-- 화면·데이터 파일 받기 --------> [호스팅 서비스] 화면 파일·데이터 파일
   |-- 공지·배너·팝업 읽어 오기 -----> [구글 시트(공지용, 공개 게시)]
   |-- 공휴일 읽어 오기 -------------> [구글 시트(공지용)의 "공휴일" 탭]
   |-- 문의·신고 보내기 ------------> [구글폼] → [응답 시트]
   |-- 방문·건물 누름 기록 ---------> [구글 애널리틱스]

[관리자(1명)]
   |-- 시간표·폐강 파일 넣기 -------> [관리자 PC 변환 도구] → 데이터 파일
   |-- 데이터 파일 다시 올리기 -----> [호스팅 서비스]
   |-- 공지·배너·팝업 적기 ---------> [구글 시트(공지용)]
   |-- 공휴일 적기 -----------------> [구글 시트(공지용)의 "공휴일" 탭]
   |-- 문의·신고 처리 --------------> [응답 시트] (+ 이메일로 문의 답변)
   |-- 방문자 수·건물 조회수 보기 --> [구글 애널리틱스]
```

| 구성 요소 | 쉬운 설명 |
|---|---|
| 사용자 화면 | 학생이 웹 브라우저로 보는 화면입니다(PC 기준, 휴대폰에서도 열림). 로그인 없이 씁니다. 날짜·교시 필터, 초기화 버튼, 캠퍼스맵, 층별 안내도, 강의실 상세, 공지·배너·팝업, 문의하기·신고하기 연결이 들어갑니다. |
| └ 캠퍼스맵 (사용자 화면의 일부) | 캠퍼스맵을 위에서 내려다본 지도 모양으로 띄워 끌어 옮기기·확대·축소가 되게 하고, 건물 자리를 누르면 그 건물의 층별 안내도로 들어갑니다. 외부 지도 서비스는 쓰지 않습니다. |
| 데이터 파일 | 학기 정보(이름·기간·업데이트 시각), 수업 시간(강의실·요일·교시), 폐강 수업, 건물·층·강의실(수용 인원), 캠퍼스맵·건물 영역을 담은 파일입니다. 공휴일 목록은 담지 않고, 구글 시트(공지용)에서 읽어 옵니다. 교시 시각표는 사이트에 미리 넣어 둡니다. 학생에 관한 정보는 담지 않습니다. |
| 호스팅 서비스 | 화면 파일과 데이터 파일을 올려 두는 곳입니다. 관리자 구글 계정으로 쓸 수 있는 서비스(예: Firebase Hosting)를 먼저 고르고, 확정은 `08_아키텍처_ADR.md`에서 정합니다. |
| 구글 시트(공지용) | 관리자가 공지사항·배너·팝업 내용을 적는 표입니다. 같은 시트의 "공휴일" 탭에는 공휴일 목록을 적습니다. 공개 게시해 두면 사이트가 읽어 옵니다. 사이트를 다시 올리지 않아도 바뀐 내용이 반영됩니다. |
| 구글폼·응답 시트 | 학생이 문의·신고를 보내는 신청서와, 그 응답이 쌓이는 표입니다. 관리자가 "처리 상태" 칸으로 관리합니다. |
| 구글 애널리틱스 | 일일 방문자 수와 건물별 조회수(건물을 누른 횟수)를 세는 무료 통계 서비스입니다. 누구인지는 알 수 없는 숫자로만 봅니다. |
| 관리자 PC 변환 도구 | 관리자 컴퓨터에서 시간표·폐강 교과목 파일을 검사하고 사이트용 데이터 파일을 만드는 프로그램입니다. 학기를 반영할 때 공개된 시트의 공휴일 탭도 읽어 확인합니다(7.6). 학생은 파일을 올리지 않습니다. |

### 5.1 데이터가 흐르는 순서

**시간표·강의실 정보**

1. 학교가 학기 시간표를 HWP 파일로 공지합니다. 폐강 교과목은 학교가 xlsx 파일로 줍니다.
2. 관리자가 시간표 내용을 **우리가 정한 엑셀/CSV 양식**으로 옮깁니다(수작업).
3. 관리자가 시간표 파일과 최종 폐강 교과목 파일을 **관리자 PC 변환 도구**에 넣습니다. 학기 이름·시작일·종료일, 층·수용 인원, 캠퍼스맵은 필요할 때 파일을 고칩니다.
4. 변환 도구가 파일을 검사합니다. 오류가 있으면 오류 줄 번호와 이유를 목록으로 보여 주고, 고쳐서 다시 넣을 때까지 반영하지 않습니다. 공개된 시트의 공휴일 탭도 읽어, 학기가 걸친 연도의 공휴일이 없으면 경고합니다(7.6).
5. 검사를 통과하면 변환 도구가 **폐강된 수업을 공실 판정에서 빼고** 사이트용 데이터 파일을 만듭니다. 같은 학기면 수업 시간 데이터를 덮어쓰고, 관리자가 직접 입력한 층·수용 인원은 남깁니다. 새 학기면 지난 학기의 수업 시간 데이터만 지웁니다.
6. 관리자가 모든 수정을 마친 뒤 데이터 파일을 사이트에 다시 올립니다. 이 올린 시각이 기준 표시의 업데이트 날짜 기준이 됩니다(7.1-5).
7. 학생이 사이트를 열면 화면과 데이터 파일을 받습니다. 필터에는 오늘 날짜와 지금 교시가 골라져 있습니다. 지금 시각은 학생 기기의 시계를 한국 시간으로 바꿔 씁니다.
8. 학생이 날짜·교시를 고르고 캠퍼스맵에서 건물을 누르면(또는 건물 목록에서 고르면), 학생 화면이 데이터 파일로 공실 / 수업중을 계산해 층별 안내도에 보여 줍니다.

**공지·공휴일·문의·통계**

9. 관리자가 공지사항·배너·팝업을 구글 시트에 적습니다. 공휴일은 같은 시트의 "공휴일" 탭에 적습니다. 학생이 사이트를 열면 사이트가 공개 게시된 시트를 읽어 와, 공지·배너·팝업을 보여 주고 공휴일을 달력에 씁니다.
10. 학생이 문의하기·신고하기를 누르면 구글폼으로 연결됩니다. 보낸 내용은 응답 시트에 쌓이고, 관리자가 처리 상태를 적어 가며 처리합니다. 문의 답변은 학생이 적은 이메일로 보냅니다. 신고에는 답장하지 않습니다.
11. 학생이 사이트를 열거나 건물을 누르면 구글 애널리틱스가 셉니다. 관리자는 이 숫자를 대시보드로 봅니다.

> 건물 고르기는 외부 지도 서비스 대신 **따로 준비한 캠퍼스맵**을 쓰기로 정했습니다. 캠퍼스맵을 무엇으로 만들지는 나중에 정합니다(7.4). 호스팅 서비스, 변환 도구를 만들 프로그래밍 언어, 데이터 파일 형식 같은 기술 제품은 이 문서에서 고르지 않습니다. `08_아키텍처_ADR.md`에서 정하고, 캠퍼스맵 선택을 포함해 선택 이유를 ADR(설계 결정 기록)로 남깁니다.

## 7. 가정·제약

### 7.1 시간표 데이터 관련 (결정 사항에서 나온 제약)

1. **학기 단위 파일로 반영한다.** 학교 학사 시스템의 공개 API(프로그램끼리 데이터를 주고받는 창구)를 찾지 못했습니다. 그래서 관리자가 한 학기 분량의 엑셀/CSV 파일을 관리자 PC 변환 도구에 넣어 반영하는 방식으로 정했습니다.
2. **한 학기 분량만 다룬다.** 학교에서 받을 수 있는 시간표는 한 학기 분량뿐입니다. 빈 강의실 찾기에는 이번 학기 정보만 있으면 됩니다.
3. **학기마다 새로 반영하고, 지난 학기 수업 시간은 지운다.** 학기마다(2월·8월쯤) 새 파일을 반영합니다. 새 학기를 반영하면 지난 학기의 **수업 시간 데이터만 지웁니다.** 건물·강의실·층·수용 인원 정보는 남깁니다. 공실은 **매 학기 그 학기 시간표의 수업 시간으로만** 판단합니다. 지난 학기에만 나오고 새 학기 시간표에 없는 강의실도 목록에 남으며, 수업이 없으므로 공실로 보입니다(숨기거나 따로 표시하지 않음).
4. **정정 기간에는 다시 반영한다.** 수강정정이 끝날 때까지 시간표가 수시로 바뀝니다. 같은 학기 파일을 다시 반영하면 수업 시간 데이터를 덮어씁니다. 관리자가 직접 입력한 층·수용 인원은 남깁니다. 앞 파일에만 있던 강의실도 목록에 남깁니다. 변환 도구가 "이번 파일에서 사라진 강의실" 목록을 알려 주므로, 오타 코드로 잘못 들어간 강의실이면 관리자가 지울 수 있습니다. 지운 강의실이 다음 파일에 다시 나오면 목록에 다시 넣습니다(7.2). 폐강 파일만 바꿔 다시 반영해도 같습니다.
5. **화면에 기준을 표시한다.** "2026-2학기 시간표 기준 · 9/15 업데이트"처럼 보여 줘서 정보가 최신인지 알게 합니다. 업데이트 날짜는 **관리자가 모든 수정을 마치고 사이트에 올린 시각**을 기준으로 합니다. 모든 수정은 시간표·폐강 교과목·캠퍼스맵·강의실 정보 등을 고친 것입니다. 구글 시트로 바꾸는 공지·배너·팝업과 공휴일 목록은 사이트를 다시 올리지 않으므로 이 시각에 넣지 않습니다. 학교가 새 자료를 공지해도, 관리자가 반영할 때까지는 기존 정보를 그대로 보여 줍니다.
   - 이 시각은 사이트에 올리기 직전에 자동으로 기록하는 방식을 제안합니다. **(제안값 — 사용자 확인 필요)** 세부는 `11_운영_배포.md`에서 정합니다.
6. **학기가 아닌 기간을 처리한다.** 관리자가 학기 시작일·종료일을 파일에 적습니다. 방학·계절학기에는 "현재 학기 수업 기간이 아닙니다"라고 안내합니다.
7. **최종 폐강 교과목을 반영한다.** 관리자가 시간표 파일과 함께 최종 폐강 교과목 파일을 반영합니다. 폐강된 수업이 잡혀 있던 시간의 강의실은 공실로 보여 줍니다. 폐강 파일에만 나오고 본 시간표에는 없는 정보(강의실·정원 등)는 강의실 목록에 추가합니다. 폐강된 수업이므로 수업 시간은 넣지 않습니다.
8. **휴강·보강·시험 일정은 알 수 없다.** 이 일정은 시간표에 나오지 않고, 특히 휴강은 예고 없이 생깁니다. 그래서 반영하지 않고, 화면에 "휴강·보강·시험 일정은 반영되지 않습니다"라고 짧게 안내합니다.

### 7.2 관리 수작업 관련

- 관리자는 **1명(사용자 본인)**입니다. 더 필요하면 나중에 추가합니다.
- **수업 시간표는 HWP 파일**입니다. HWP는 프로그램이 자동으로 읽기 어려워서, 관리자가 이 내용을 **우리가 정한 엑셀/CSV 양식으로 옮기는 수작업**이 필요합니다.
- **폐강 교과목은 xlsx(엑셀) 파일**입니다. 학교 파일을 그대로 변환 도구에 넣습니다. 학교 파일의 칸 구성이 학기마다 같은지는 파일을 받아 확인합니다.
- 옮기는 과정에서 실수가 생길 수 있습니다. 그래서 변환 도구가 파일을 검사합니다. 오류 줄 번호와 이유를 보여 주고, 고칠 때까지 반영하지 않습니다. 같은 강의실·요일·교시에 수업이 겹치면 관리자에게 경고로 알립니다(03 FR-024).
- 시간표 엑셀/CSV 양식(어떤 칸을 둘지)은 03·06에서 정합니다. 폐강 교과목 파일과 **같은 과목을 맞춰 볼 수 있는 칸**(예: 과목 코드·분반)이 꼭 있어야 합니다.
- **교시 시각표(확정)**: 1교시 09:00 시작, 매 교시 정시 시작, 50분 수업·10분 쉬는 시간, 1~9교시.

  | 교시 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
  |---|---|---|---|---|---|---|---|---|---|
  | 시작 | 09:00 | 10:00 | 11:00 | 12:00 | 13:00 | 14:00 | 15:00 | 16:00 | 17:00 |
  | 끝 | 09:50 | 10:50 | 11:50 | 12:50 | 13:50 | 14:50 | 15:50 | 16:50 | 17:50 |

  - 교시 규칙이 고정이므로 관리자가 학기마다 입력하지 않고, 사이트에 미리 넣어 둡니다.
  - 쉬는 시간(예: 09:50~10:00)에는 다음 교시 기준으로 보여 줍니다.
  - **야간 수업은 지원하지 않습니다.** 학교 안내에는 10교시(~18:50)와 야간 수업(18:00~22:05)도 있지만, 이 서비스는 1~9교시(09:00~17:50)만 다룹니다. 필터에서도 1~9교시만 고를 수 있습니다.
  - 지금이 수업 시간(1~9교시) 밖이면(09:00 이전, 17:50 이후), 교시를 직접 고르라고 안내합니다(7.6).
- **강의실 목록**(건물·호실)은 시간표에 나오는 강의실로 만듭니다. 폐강 파일에만 나오는 강의실도 추가합니다(7.1-7). 시간표·폐강 파일에 한 번도 안 나오는 방은 수업용 강의실이 아닌 것으로 봅니다.
  - 관리자가 지운 강의실(7.1-4)이 다음에 반영하는 시간표·폐강 파일에 다시 나오면, 목록에 다시 넣습니다. 새 파일에 나왔다면 실제로 쓰는 강의실이기 때문입니다. 이때 변환 도구가 "다시 추가된 강의실" 목록을 관리자에게 알려 줍니다.
    - 다시 넣을 때는 보관해 둔 값(관리자가 전에 적은 층·수용 인원, 지난 학기까지의 최댓값)을 되살립니다. 관리자가 적은 값이 우선이라는 규칙은 그대로입니다.
- **강의실 코드**: 시간표에는 강의실이 "A18101"처럼 코드로 나옵니다. 이 코드를 건물·호실과 짝짓는 규칙은 사용자가 나중에 알려 줍니다. **(확인 필요)**
- **건물 이름 표시**: 화면에는 "공과대학 1호관(D2)"처럼 건물 이름 뒤에 캠퍼스맵의 건물 번호를 붙입니다.
- **수용 인원**은 학교 홈페이지에 강의실별로 모여 있지 않습니다(2026-09 조사). 일부 단과대학 건물 소개 페이지에만 몇몇 강의실이 나옵니다(예: 사범대학1호관 제1합동강의실 120명, 사범대학2호관 제2합동강의실 80명). 그래서 **수강 정원으로 수용 인원을 추정**합니다.
  - **지금까지 반영한 모든 학기**에서 그 강의실에 잡힌 수업들의 수강 정원 중 **가장 큰 값**을 "약 N명(추정)"으로 보여 줍니다. 그만큼의 학생이 그 방에서 수업을 듣도록 잡혔기 때문입니다.
  - 새 학기를 반영할 때는 남겨 둔 값과 새 학기 수강 정원 중 큰 값을 남깁니다.
  - 같은 학기 파일을 다시 반영하면(예: 수강정정 기간) 이번 학기 최댓값은 새 파일로 다시 계산하고, 지난 학기까지의 최댓값과 비교해 큰 값을 씁니다. 앞서 반영한 같은 학기 값은 남기지 않습니다. 폐강 파일만 바꿔 다시 반영해도 같은 규칙으로 다시 계산합니다.
  - 폐강 수업의 수강 정원도 계산에 넣습니다. 본 시간표에도 나오는 강의실과 폐강 파일에만 나오는 강의실에 똑같이 적용합니다.
  - 홈페이지에 수용 인원이 나온 강의실은 관리자가 적은 그 값을 항상 우선 씁니다.
  - 홈페이지 값을 "(추정)" 없이 보일지는 사용자가 올려 줄 파일을 보고 정합니다. **(확인 필요)**
  - HWP 시간표에 **과목별 수강 정원(인원 제한) 칸이 있음**을 확인했습니다.
- 건물의 **층 구성**은 강의실 번호로 대부분 알 수 있습니다(예: 305호 → 3층). 번호로 알 수 없는 예외 강의실만 관리자가 층을 따로 입력합니다. 층을 끝내 알 수 없는 강의실을 화면에 어떻게 보일지는 사용자가 보고 판단합니다. **(확인 필요 — 사용자 판단)**
- 캠퍼스맵 위에서 **건물마다 누를 수 있는 영역**을 관리자가 한 번 정해 둡니다. 캠퍼스맵이 바뀌면 다시 맞춥니다.

### 7.3 학교와의 관계

- 시간표·폐강 교과목은 학교 홈페이지에 공개된 자료이므로, **화면에 출처를 밝히고** 씁니다. 예: "출처: 국립순천대학교 수업시간표(2026-2학기) · 폐강 교과목 안내"
- 교무학사과에 시간표 **엑셀 원본**을 받을 수 있는지 물어보면 HWP를 옮기는 수작업을 줄일 수 있습니다(선택 사항).
- 학사 시스템 연동·공개 시간표 자동 수집은 학교 허락을 받은 뒤 다음 단계에서 검토합니다.
- 나중에 **학교 공식 앱과 연동하거나 공식 앱에 편입**될 수 있습니다. 이때 쉽게 옮길 수 있도록, 학생 로그인·계정은 이번에 만들지 않습니다.

### 7.4 캠퍼스맵 관련

- 건물 고르기에는 외부 지도 서비스(카카오맵 등)를 쓰지 않고, **따로 준비한 캠퍼스맵**을 씁니다. (카카오맵 방식은 철회)
- **캠퍼스맵을 무엇으로 만들지는 나중에 정합니다(보류).** 후보는 학교 홈페이지의 캠퍼스맵 그림, 사진, 직접 만든 지도 등입니다. 04·목업 단계에서 정합니다.
- 어느 것으로 만들든 캠퍼스맵은 **위에서 내려다본 지도 모양**으로 보이고, 아래 동작이 되어야 합니다.
  - 휴대폰: 한 손가락으로 끌어 옮기기, 두 손가락으로 확대·축소
  - PC: 마우스로 끌어 옮기기, 휠로 확대·축소
  - 건물 이름은 확대해도 읽을 수 있게 지도 위에 글자로 따로 올립니다.
- 지도 위에 건물마다 누를 수 있는 영역을 만들어, 건물을 누르면 **층별 안내도**로 넘어가게 합니다.
- 캠퍼스맵 관리(캠퍼스맵 그림 교체, 건물 영역 설정)는 **관리자 기능**입니다. 파일을 고쳐 사이트를 다시 올리는 방식으로 합니다.
- 그림이나 사진을 쓰면 너무 크게 확대할 때 흐려질 수 있습니다. 확대할 수 있는 최대 크기는 캠퍼스맵을 정할 때 함께 정합니다(04·05).
- 외부 지도 서비스를 쓰지 않으므로 **사용료·사용량 한도 걱정이 없습니다.**
- **GPS로 "내 위치"를 표시하지 않습니다.** 학생이 건물을 직접 눌러 고릅니다.
- 학교 자료(그림·사진 등)를 쓰면 **화면에 출처를 밝힙니다.** 예: "캠퍼스맵 출처: 국립순천대학교"
- 캠퍼스맵의 건물 중 **강의실이 있는 건물만** 누를 수 있게 합니다(예: 학생생활관·체육관 등은 제외).
- 건물 목록의 **정렬 순서는 보류**입니다(나중에 정함). 후보로 "캠퍼스맵 건물 번호(D2 등) 순"이 있습니다.

### 7.5 층별 안내도 관련

- 층별 안내도는 건물을 고르면 **층마다 강의실 호실과 공실 / 수업중**을 보여 주는 화면입니다. 학생은 층별로 스크롤하며 봅니다. 그림 모양은 아래처럼 보류 중입니다.
- 층 구성은 강의실 번호로 정합니다(7.2 참고). 강의실이 하나도 없는 층은 보여 주지 않거나 "강의실 없음"으로 표시합니다(04에서 정함).
- **그림 모양은 나중에 다시 정합니다(보류).** 다시 짤 가능성이 높아, 화면을 만들 때(`04_화면설계서.md`·목업 단계) 다시 결정합니다. 후보는 다음과 같습니다.
  1. **강의실 배치 그림**: 층마다 강의실이 실제로 놓인 모양을 그림으로 보여 줌. 학교에 공개된 평면도가 없으므로 배치를 직접 그려야 함
  2. **실제 지도 참고**: 실제 지도를 참고해 건물 위치와 **위에서 본 건물 모양**을 그리고, 그 위에 강의실을 배치함(그릴 때 참고만 하며, 외부 지도 서비스를 화면에 넣는 것은 아님)
  3. **목록 모양**: 층을 위아래로 쌓고 층마다 강의실을 나열함(가장 간단한 대안)
- **공실 / 수업중을 어떤 모양으로 보여 줄지도 보류**입니다. 사용자가 목업을 보고 정합니다.
- 어떤 방식이든 **"날짜·교시 → 건물 → 층 → 공실"을 찾는 흐름은 같습니다(확정).** 03 기능명세서는 이 흐름을 기준으로 씁니다.
- 그림 모양은 `04_화면설계서.md`·목업 단계에서 정합니다(보류).

### 7.6 시간 기준·운영일 관련

- **시간 기준은 학생 기기의 시계입니다.** 자체 서버가 없어 서버 시각을 쓸 수 없습니다. 그래서 학생 기기의 시계를 **한국 시간(KST)으로 바꿔** 씁니다. 해외 시간대로 설정된 기기도 한국 시간으로 계산합니다.
  - 기기 시계는 보통 인터넷 표준 시각에 자동으로 맞춰집니다. 오차는 최대한 줄이며, 목표치는 03 NFR-009에 제안값으로 둡니다.
- **처음 열었을 때 기본값은 오늘 날짜와 지금 교시**입니다. 쉬는 시간에는 다음 교시를 기준으로 합니다. 지금이 수업 시간(1~9교시) 밖이면 교시를 직접 고르라고 안내합니다.
- **화면은 자동으로 바뀌지 않습니다.** 화면을 켜 둔 채 교시가 바뀌면, 학생이 초기화 버튼을 누릅니다.
- **지난 교시도 고를 수 있습니다.** 오늘 이미 지난 교시를 골라도 됩니다.
- **주말·공휴일은 운영하지 않습니다.**
  - 필터 달력에서 주말·공휴일 날짜는 흐리게 보이고, 누를 수 없습니다(고를 수 없음).
  - 단, 오늘이 주말·공휴일이면 기본 날짜는 오늘이 됩니다. 이때 캠퍼스맵(또는 건물 목록)에서 건물을 누르면 "운영하지 않는 날입니다" 같은 문구를 보여 줍니다.
  - 시간표 파일에 토요일·일요일 수업 줄이 있으면 저장하지 않고 경고로 알리는 방식을 제안합니다. **(제안값 — 사용자 확인 필요)**
- **공휴일 목록은 관리자가 손으로 적습니다.** 달력 부품은 공휴일을 스스로 알지 못합니다. 그래서 관리자가 **공지용 구글 시트의 "공휴일" 탭**에 **매년 한 번** 그해 공휴일을 적습니다. 임시공휴일·학교 휴업일이 생기면 관리자가 추가합니다.
  - 공지사항·배너·팝업을 적는 구글 시트(공지용)에 탭을 하나 더 둔 것입니다.
  - 공개 게시된 시트이므로 **사이트를 다시 올리지 않아도 반영됩니다.** 공지와 마찬가지로 바꾼 뒤 몇 분 늦게 보일 수 있습니다(03 FR-020).
  - 탭의 칸 구성은 `06_데이터모델_ERD.md`에서 정합니다.
  - 학생이 사이트를 열면 사이트가 이 탭을 읽어 옵니다. 불러오지 못하면 달력에서 주말만 막고, 필터 밑에 "공휴일 정보를 불러오지 못했습니다"를 짧게 안내합니다. 이때 공휴일이 평일처럼 보일 수 있습니다(확정).
  - 탭에 적지 않은 휴일은 운영하는 날로 보입니다. 관리자가 추가할 때까지 그렇습니다.
  - 변환 도구는 학기를 반영할 때 공개된 시트의 공휴일 탭을 읽어 확인합니다. 반영하는 학기의 기간(시작일~종료일)이 걸친 연도의 공휴일이 없으면 경고합니다. 예: 2026-2학기(9~12월)라면 2026년 공휴일이 있는지 확인합니다. 학기가 두 해에 걸치면 두 해 모두 확인합니다. 경고 문구는 "2026년 공휴일 목록이 없습니다"처럼 빠진 연도를 알려 줍니다(확정).
  - 변환 도구가 시트를 읽지 못하면 "공휴일 시트를 읽지 못했습니다"라고 경고하고, 학기 반영은 계속합니다. 공휴일은 데이터 파일에 담지 않아 반영 결과에 영향이 없기 때문입니다. **(제안값 — 사용자 확인 필요)**
  - 날짜 형식이 틀린 줄은 사이트가 그 줄만 건너뜁니다. 변환 도구는 학기를 반영할 때 몇째 줄이 틀렸는지 경고로 알려 줍니다. **(제안값 — 사용자 확인 필요)**
  - 탭을 불러왔는데 공휴일이 한 줄도 없으면, 달력에서 주말만 막고 학생 화면에는 따로 안내하지 않습니다. 빠진 공휴일은 변환 도구의 경고로 관리자가 알아챕니다. **(제안값 — 사용자 확인 필요)**
  - 외부 공휴일 서비스(API)는 쓰지 않습니다. 정적 사이트에서는 인증키가 드러나기 때문입니다. 공휴일 탭은 관리자가 직접 적는 것이므로 외부 공휴일 서비스가 아닙니다.

### 7.7 정적 사이트·외부 도구 관련

- **호스팅 서비스는 관리자 구글 계정으로 쓸 수 있는 서비스를 먼저 고릅니다.** 예: Firebase Hosting. 이 서비스는 사이트 올리기 기능만 씁니다. 확정은 `08_아키텍처_ADR.md`에서 정합니다.
- **공개 전에는 로컬 PC(관리자 본인의 컴퓨터)에서 사이트를 실행해 확인합니다.** 이 기간은 목업 확인·개발·시연 단계입니다. 인터넷에는 아직 공개하지 않습니다.
  - 로컬 PC는 확인용입니다. 서비스를 운영하는 곳이 아닙니다.
  - 호스팅 서비스는 학생들에게 공개할 때 정합니다. 구글 계정으로 쓸 수 있는 서비스를 먼저 고르고, `08_아키텍처_ADR.md`에서 확정합니다.
- 시간표·강의실·학기·캠퍼스맵 정보를 바꾸면 **관리자가 사이트를 다시 올려야** 학생 화면에 반영됩니다.
- 공지사항·배너·팝업과 공휴일 목록은 구글 시트에서 고치면 사이트를 다시 올리지 않아도 반영됩니다(7.6). 그래서 기준 표시의 업데이트 시각(7.1-5)에는 넣지 않습니다.
- **공지용 구글 시트는 공개 게시됩니다.** 누구나 읽을 수 있으므로, 이 시트에는 공지와 공휴일 외의 정보를 넣지 않습니다. 문의·신고가 쌓이는 응답 시트는 공개 게시하지 않습니다.
- **문의 이메일은 개인정보입니다.**
  - 1:1 문의의 이메일 칸은 **선택 사항**입니다. 적을 때는 **동의 체크**를 받습니다.
  - 이메일을 적지 않으면 답장을 받을 수 없다고 안내합니다.
  - 이메일은 구글폼(응답 시트)에만 저장되고, 처리한 뒤 지웁니다. 보관 기간은 `09_보안_개인정보.md`에서 정합니다.
  - 신고 폼에는 이메일 칸이 없습니다. 신고에는 답장하지 않고 처리만 합니다.
- **관리자 계정 보안**: 사이트 안에 로그인이 없습니다. 그래서 관리에 쓰는 계정을 **관리자 구글 계정 하나**로 합칩니다. 구글폼·구글 시트·구글 애널리틱스·호스팅 서비스를 모두 이 계정으로 씁니다. 이 계정에는 2단계 인증을 권장합니다. 세부는 `09_보안_개인정보.md`에서 정합니다.
- **방문 통계**: 구글 애널리틱스로 일일 방문자 수와 건물 조회수를 봅니다. 같은 브라우저는 하루에 1번만 셉니다. 사이트는 누구인지 저장하지 않으며, 누구인지 알 수 없는 숫자로만 봅니다. 구글 애널리틱스 식별값(쿠키) 안내·동의 여부는 `09_보안_개인정보.md`에서 정합니다.
- 신고하기의 신고 대상과 폼에 미리 채울 내용은 `03_기능명세서.md` FR-011에 제안값으로 적었습니다. 신고에는 답장하지 않습니다(확정).

### 7.8 기타 제약

- 이번에는 **PC 웹을 먼저** 만듭니다. PC 화면을 기준으로 설계하고, 휴대폰 브라우저에서도 깨지지 않게 합니다. 휴대폰 전용 화면·앱은 다음 단계에서 검토합니다.
- 예상 사용자는 약 7,000명이고 동시 접속은 적을 것으로 봅니다. 자체 서버가 없으므로, 호스팅 서비스의 사용량 한도 안에서 운영할 수 있는지는 `08_아키텍처_ADR.md`에서 확인합니다.
- 학교 공식 앱과는 이번에 연동하지 않습니다.
- 기술스택(쓸 프로그램·도구)은 정하지 않았습니다. `08_아키텍처_ADR.md`에서 정합니다.
- **사이트는 학생 정보를 저장하지 않습니다.** 학생 로그인·알림·즐겨찾기가 없고, 위치 정보도 쓰지 않습니다. 학생 정보는 **문의할 때 이메일만** 받고(선택 입력·동의), 처리 후 지웁니다(7.7).
