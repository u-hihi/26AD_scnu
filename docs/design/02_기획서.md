## 1. 배경·목적

### 1.1 배경

- 순천대학교 학생은 수업 사이에 애매하게 빈 시간이 자주 생깁니다. 이 시간을 **공강**이라고 부릅니다.
- 공강에 공부하거나 쉴 곳으로 빈 강의실을 쓰고 싶어도, 어느 강의실이 비어 있는지 알기 어렵습니다.
- 지금은 건물을 돌아다니며 문을 열어 보거나, 시간표를 직접 뒤져 봐야 합니다.
- 학교 공식 시간표는 학기마다 공지사항에 HWP(한글 문서) 파일로 올라옵니다. 따로 "실시간 조회" 페이지(향림통시스템)도 있습니다.
- 하지만 이 자료들은 "지금 어느 강의실이 비었는지"를 한눈에 보여 주지 않습니다.

### 1.2 목적

- 학생이 웹 브라우저(PC·휴대폰)로 **지금 비어 있는 강의실을 바로 찾게** 합니다.
- 원하는 시간·건물로 빈 강의실을 미리 찾아볼 수 있게 합니다.
- 강의실의 수용 인원·다음 수업 시각을 함께 보여 줘서, 얼마나 오래 쓸 수 있는지 판단하게 돕습니다.

### 1.3 성공의 모습 (정성 목표)

- 학생은 **앞 수업이 끝난 건물이나 다음 수업이 있는 건물**을 기준으로 빈 강의실을 찾습니다. 멀리 이동하지 않고 그 건물 안에서 고르는 것이 보통입니다.
- 그래서 학생이 **위에서 내려다본 지도 모양의 캠퍼스맵을 움직이고 확대해 건물을 누르면 → 층별 안내도가 나오고 → 층마다 그 시간대의 빈 강의실**이 보이는 흐름으로(안내도 모양은 7.5 참고), 헤매지 않고 찾을 수 있어야 합니다.
- 학생이 앱을 설치하지 않고 웹 브라우저로 쓸 수 있습니다. **PC 화면을 기준**으로 만들되, 휴대폰 브라우저로 열어도 깨지지 않습니다.
- 사용자가 화면에서 "이 정보가 언제 기준인지"를 항상 알 수 있습니다.
- 숫자로 된 목표(응답 속도 등)는 아직 정하지 않았습니다. **(확인 필요)** — `03_기능명세서.md`의 NFR·SLO(비기능 요구·목표 수준)에서 정합니다.

## 2. 대상·사용자

| 구분 | 누구 | 하는 일 | 주로 쓰는 화면 |
|---|---|---|---|
| 학생 사용자 | 순천대학교 학생 | 건물·층별 빈 강의실 찾기, 시간·건물 검색, 강의실 상세 보기 | 사용자 화면(웹) |
| 운영자 | 서비스를 개발한 사람(개발자가 운영도 함) | 학기 시간표·폐강 교과목 파일 올리기, 학기 기간 입력, 건물·층·강의실 정보 관리 | 관리자 화면(학생에게는 숨김, 관리자 로그인 필요) |

- 이번에는 **PC 웹을 먼저** 만듭니다. 다만 공강에 이동하면서 휴대폰으로 열 수도 있으므로, 휴대폰 브라우저에서도 화면이 깨지지 않게 합니다(반응형).
- **학생 로그인은 넣지 않습니다.** 운영자만 별도의 **관리자 로그인**으로 관리자 화면에 들어갑니다. 나중에 학교 공식 앱과 연동하거나 공식 앱에 편입될 수 있어, 계정 기능은 그때 학교 계정에 맞추는 편이 낫습니다. 학생에 관한 정보는 **서버에 아무것도 저장하지 않습니다.**
- 예상 사용자는 **약 7,000명**입니다. 모두가 한꺼번에 접속하지는 않을 것으로 봅니다(동시 접속은 적음).

### 2.1 대표 사용 장면

1. 2교시 수업이 공대 1호관에서 끝났고, 4교시까지 1시간이 빕니다. 학생이 서비스를 열어 캠퍼스맵을 손가락으로 끌고 확대해 **공대 1호관을 누르면** 층별 안내도가 나오고, 3층에 지금 빈 강의실이 표시되어 있습니다(예시 장면).
2. 학생이 한 강의실을 누르면 "약 30명(추정) · 다음 수업 11:00 시작"이 보입니다.
3. 내일 오후 조별 모임 장소를 찾으려고 "내일 5~7교시, 공대 1호관"으로 검색합니다.

## 3. 범위(할 것/안 할 것)

### 3.1 이번에 할 것

| 임시 번호 | 기능 | 쉬운 설명 |
|---|---|---|
| 기능 1 | 캠퍼스맵에서 건물 고르기 | 캠퍼스맵을 **위에서 내려다본 지도 모양**으로 보여 주고, **끌어서 옮기고 확대·축소**하며 건물을 눌러 고릅니다. 캠퍼스맵 대신 건물 목록에서 고를 수도 있습니다. |
| 기능 2 | 층별 안내도로 빈 강의실 보기 | 고른 건물의 층별 안내도가 나오고, 층마다 지금(또는 고른 시간대) 빈 강의실이 표시됩니다. 층을 누르면 그 층 강의실을 자세히 봅니다(안내도 모양과 조작 방식은 04·목업에서 정함). |
| 기능 3 | 시간·건물로 검색 | "오늘 3~5교시, 공대 1호관"처럼 시간과 건물을 골라 빈 강의실을 찾습니다. |
| 기능 4 | 강의실 상세 정보 | 수용 인원("약 N명(추정)"으로 표시), 다음 수업이 시작하는 시각을 보여 줍니다. |

> 정식 FR 번호는 `03_기능명세서.md`에서 부여합니다.
> `idea.md`의 기능 "지금 빈 강의실 목록"은 기능 1·2(캠퍼스맵 → 건물 → 층 → 빈 강의실)로 구체화했습니다.

이 기능들을 돌리기 위해 함께 필요한 것:

- **관리자 기능(학생에게는 숨김)**: 운영자가 관리자 로그인 후 쓰는 화면입니다. 서비스 데이터의 출발점입니다. `03_기능명세서.md`에서 "관리자 기능"으로 따로 번호를 붙입니다.
  - 한 학기 시간표 파일(우리 양식 엑셀/CSV: 표 형식 파일)과 **최종 폐강 교과목 파일**(학교가 주는 xlsx: 엑셀 파일) 올리기
  - 학기 이름·기간 입력
  - 캠퍼스맵 위 건물 영역·층·강의실(수용 인원) 정보 관리
- **웹(PC 우선)**: 브라우저에서 쓰는 웹 화면입니다. 설치하는 앱이 아닙니다. PC 화면을 기준으로 하고, 휴대폰 브라우저에서도 열립니다.

### 3.2 이번에 안 할 것 (범위 밖)

- 학교 공식 앱과 연동하거나, 공식 앱에 기능을 추가하는 것 (나중에 연동·편입 가능성은 열어 둠)
- 휴대폰 전용 화면(모바일 버전)과 안드로이드·iOS(아이폰 운영체제) 앱 (웹을 먼저 만든 뒤 검토)
- 학생 로그인·계정 기능 (공식 앱 연동 시 학교 계정에 맞춰 검토. 운영자용 관리자 로그인은 있음)
- 학사 시스템과의 자동 연동 (학교 승인 필요, 다음 단계 후보)
- 공개 시간표 페이지 자동 수집(크롤링: 프로그램이 웹 페이지 내용을 자동으로 긁어 오는 것) (학교 허락 필요, 다음 단계 후보)
- 휴강·보강·시험 일정 (알 수 없어 반영하지 않음. 특히 휴강은 예고 없이 생김)
- 야간 수업 시간대(18:00 이후) (지원하지 않음)
- 외부 지도 서비스(카카오맵 등)·GPS(위성으로 현재 위치를 알아내는 기능) 현재 위치 표시 (캠퍼스맵을 따로 준비해 쓰므로 제외)
- 강의실 콘센트 정보
- 알림(웹 푸시)·즐겨찾기·공강 시간 입력 (수업은 매주 같은 시간·같은 장소에서 열려 알림의 필요성이 낮으므로 제외)

## 4. 핵심 개념·용어

| 용어 | 뜻 |
|---|---|
| 공강 | 수업과 수업 사이에 비는 시간 |
| 빈 강의실 | 해당 시간에 시간표상 수업이 잡혀 있지 않은 강의실. 실제로 사람이 없는지는 보장하지 않습니다. |
| 교시 | 수업 시간을 나누는 단위. 1교시는 09:00에 시작하고, 매 교시 정시에 시작해 50분 수업·10분 쉬는 시간. 1~9교시(야간 수업은 지원하지 않음) |
| 교시 시각표 | 각 교시가 몇 시 몇 분에 시작·끝나는지 적은 표 (7.2의 표 참고) |
| 건물 | 강의실이 속한 교내 건물 (예: 공대 1호관). 캠퍼스맵 위에 표시됩니다. |
| 층 | 건물 안의 층. 건물을 고르면 층별 안내도로 나옵니다. |
| 층별 안내도 | 건물의 층마다 어떤 강의실이 있고 비어 있는지 보여 주는 화면입니다. 모양은 04·목업에서 정합니다. |
| 강의실 | 수업이 열리는 방. 호실 번호·층·수용 인원 같은 속성을 가짐 |
| 수용 인원(추정) | 그 강의실에서 열리는 수업의 수강 정원 중 가장 큰 값. 실제 좌석 수와 다를 수 있어 "약 N명(추정)"으로 표시 |
| 시간표 | 어떤 강의실에서 무슨 요일·몇 교시에 수업이 있는지 적은 자료 |
| 학기 | 시간표가 적용되는 기간. 예: 2026-2학기. 시작일·종료일을 가짐 |
| 수업 기간 | 학기 시작일부터 종료일까지. 방학·계절학기는 수업 기간이 아님 |
| 수강정정 | 학기 초에 수강 과목을 바꾸는 기간. 이 기간에는 시간표가 자주 바뀜 |
| 시간표 파일 | 운영자가 올리는 한 학기 분량의 엑셀/CSV 파일. 학교가 HWP로 공지한 시간표를 우리가 정한 양식으로 옮긴 것 |
| xlsx | 엑셀 파일 형식. 학교가 폐강 교과목 목록을 이 형식으로 제공함 |
| 폐강 교과목 | 수강 인원 부족 등으로 열리지 않게 된 수업. 시간표에는 있지만 실제로는 수업이 없으므로, 그 시간의 강의실은 비어 있는 것으로 봅니다. |
| 폐강 교과목 파일 | 학교가 수강정정 뒤 확정하는 폐강 수업 목록. 운영자가 시간표 파일과 함께 올립니다. |
| CSV | 쉼표로 칸을 나눈 단순한 표 파일 형식. 엑셀에서 열고 저장할 수 있음 |
| 업로드 | 파일을 서비스에 올리는 것. 같은 학기를 다시 올리면 기존 데이터를 덮어씀 |
| 기준 표시 | "2026-2학기 시간표 기준 · 9/15 업데이트"처럼 정보가 언제 기준인지 화면에 보여 주는 것 |
| 운영자 | 시간표 파일을 올리고 학기·건물 정보를 관리하는 사람. 이 서비스에서는 개발자가 맡음 |
| 관리자 화면·관리자 로그인 | 운영자만 쓰는 숨겨진 화면과, 그 화면에 들어가기 위한 로그인. 학생 화면에는 보이지 않음 |
| 웹 | 크롬·엣지·사파리 같은 브라우저로 여는 서비스. 앱 설치가 필요 없음 |
| 반응형 | 화면 크기(PC·휴대폰)에 맞춰 화면 배치가 알아서 바뀌는 것 |
| 캠퍼스맵 | 이 서비스에서 보여 주는 학교 지도. 무엇으로 만들지(학교 배치도 그림·사진·직접 제작 등)는 나중에 정합니다(7.4). 위에서 내려다본 지도 모양으로 보이고, 끌어서 옮기고 확대·축소할 수 있으며, 건물 자리를 누를 수 있습니다. |
| 확대·축소·끌어 옮기기 | 휴대폰에서 두 손가락을 벌리거나(확대) 오므리고(축소), 한 손가락으로 끌어 보는 곳을 옮기는 동작. PC에서는 마우스 휠과 끌기로 합니다. |

> 이 용어들은 나중에 `13_용어집.md`에 가나다순으로 모읍니다.

## 5. 시스템 구성 개요

서비스는 크게 네 부분(사용자 화면·관리자 화면·서버·데이터 저장소)으로 이루어집니다. 캠퍼스맵은 사용자 화면의 일부입니다.

```
 [학생 PC·휴대폰]                      [운영자 PC]
 사용자 화면(웹)                       관리자 화면(숨김, 관리자 로그인)
  - 캠퍼스맵에서 건물 고르기            - 시간표·폐강 교과목 파일 올리기
  - 층별 안내도로 빈 강의실             - 학기 이름·시작일·종료일 입력
  - 시간·건물 검색                      - 건물·층·강의실 정보 입력
  - 강의실 상세                                |
     |                                         |
     +-------------> [ 서버 ] <----------------+
                  - 파일 내용 읽기·검사, 폐강 수업 빼기
                  - "지금/그 시간에 빈 강의실" 계산
                            |
                     [ 데이터 저장소 ]
                  - 학기 정보(이름·기간·업데이트 날짜)
                  - 캠퍼스맵·건물 영역·층·강의실(수용 인원)
                  - 시간표(강의실·요일·교시)
                  - 교시 시각표
```

| 구성 요소 | 쉬운 설명 |
|---|---|
| 사용자 화면 | 학생이 웹 브라우저로 보는 화면입니다(PC 기준, 휴대폰에서도 열림). 로그인 없이 씁니다. |
| └ 캠퍼스맵 (사용자 화면의 일부) | 캠퍼스맵을 위에서 내려다본 지도 모양으로 띄워 끌어 옮기기·확대·축소가 되게 하고, 건물 자리를 누르면 그 건물의 층별 안내도로 들어갑니다. 외부 지도 서비스는 쓰지 않습니다. |
| 관리자 화면 | 운영자가 관리자 로그인 후 시간표·폐강 교과목 파일을 올리고 학기·건물 정보를 입력하는 화면입니다. 학생 화면에는 메뉴가 보이지 않습니다. |
| 서버 | 화면의 요청을 받아 빈 강의실을 계산하고 결과를 돌려주는 프로그램입니다. |
| 데이터 저장소 | 시간표·건물·강의실·학기 정보를 보관하는 곳입니다. 학생에 관한 정보는 보관하지 않습니다. |

### 5.1 데이터가 흐르는 순서

1. 학교가 학기 시간표를 HWP 파일로 공지합니다.
2. 운영자가 그 내용을 **우리가 정한 엑셀/CSV 양식**으로 옮깁니다(수작업). 폐강 교과목은 학교가 xlsx로 주므로 그대로 올립니다.
3. 운영자가 관리자 로그인 후 관리자 화면에서 시간표 파일과 최종 폐강 교과목 파일을 올리고, 학기 이름·시작일·종료일을 입력합니다.
4. 서버가 파일을 검사한 뒤 **폐강된 수업을 시간표에서 빼고** 데이터 저장소에 저장합니다. 같은 학기 파일이면 덮어씁니다.
5. 학생이 캠퍼스맵에서 건물을 누르면, 서버가 현재 시각(또는 고른 시간)·교시 시각표·시간표를 비교해 그 건물의 층별 빈 강의실을 층별 안내도로 보여 줍니다.
6. 학생이 시간·건물로 검색하면, 서버가 같은 방법으로 그 시간대의 빈 강의실을 찾아 보여 줍니다.

> 건물 고르기는 외부 지도 서비스 대신 **따로 준비한 캠퍼스맵**을 쓰기로 정했습니다. 캠퍼스맵을 무엇으로 만들지는 나중에 정합니다(7.4). 그 밖의 기술 제품(프로그래밍 언어, 데이터베이스 종류, 서버를 둘 곳 등)은 이 문서에서 고르지 않습니다. `08_아키텍처_ADR.md`에서 정하고, 캠퍼스맵 선택을 포함해 선택 이유를 ADR(설계 결정 기록)로 남깁니다.

## 7. 가정·제약

### 7.1 시간표 데이터 관련 (결정 사항에서 나온 제약)

1. **학기 단위 파일 업로드로 받는다.** 학교 학사 시스템의 공개 API(다른 프로그램이 데이터를 가져가는 창구)를 찾지 못했습니다. 그래서 운영자가 한 학기 분량의 엑셀/CSV 파일을 올리는 방식으로 정했습니다.
2. **한 학기 분량만 다룬다.** 학교에서 받을 수 있는 시간표는 한 학기 분량뿐입니다. 빈 강의실 찾기에는 이번 학기 정보만 있으면 됩니다.
3. **학기마다 새로 올린다.** 학기마다(2월·8월쯤) 새 파일을 올립니다. 데이터에 학기 이름(예: 2026-2학기)을 붙여 지난 학기와 섞이지 않게 합니다.
4. **정정 기간에는 다시 올린다.** 수강정정이 끝날 때까지 시간표가 수시로 바뀝니다. 같은 학기 파일을 다시 올리면 기존 데이터를 덮어씁니다.
5. **화면에 기준을 표시한다.** "2026-2학기 시간표 기준 · 9/15 업데이트"처럼 보여 줘서 정보가 최신인지 알게 합니다.
6. **학기가 아닌 기간을 처리한다.** 운영자가 파일을 올릴 때 학기 시작일·종료일을 함께 입력합니다. 방학·계절학기에는 "현재 학기 수업 기간이 아닙니다"라고 안내합니다.
7. **최종 폐강 교과목을 반영한다.** 운영자가 시간표 파일과 함께 최종 폐강 교과목 파일을 올립니다. 폐강된 수업이 잡혀 있던 시간의 강의실은 빈 강의실로 보여 줍니다.
8. **휴강·보강·시험 일정은 알 수 없다.** 이 일정은 시간표에 나오지 않고, 특히 휴강은 예고 없이 생깁니다. 그래서 반영하지 않고, 화면에 "휴강·보강·시험 일정은 반영되지 않습니다"라고 짧게 안내합니다.

### 7.2 운영 수작업 관련

- 운영자는 **서비스를 개발한 사람**이 맡습니다.
- **수업 시간표는 HWP 파일**입니다. HWP는 프로그램이 자동으로 읽기 어려워서, 운영자가 이 내용을 **우리가 정한 엑셀/CSV 양식으로 옮겨 올리는 수작업**이 필요합니다.
- **폐강 교과목은 xlsx(엑셀) 파일**입니다. 학교 파일을 그대로 올리고, 서버가 읽습니다. 학교 파일의 칸 구성이 학기마다 같은지는 파일을 받아 확인합니다.
- 옮기는 과정에서 실수가 생길 수 있습니다. 업로드할 때 파일을 검사하는 방법은 03에서 정합니다.
- 시간표 엑셀/CSV 양식(어떤 칸을 둘지)은 03·06에서 정합니다. 폐강 교과목 파일과 **같은 과목을 맞춰 볼 수 있는 칸**(예: 과목 코드·분반)이 꼭 있어야 합니다.
- **교시 시각표(확정)**: 1교시 09:00 시작, 매 교시 정시 시작, 50분 수업·10분 쉬는 시간, 1~9교시.

  | 교시 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
  |---|---|---|---|---|---|---|---|---|---|
  | 시작 | 09:00 | 10:00 | 11:00 | 12:00 | 13:00 | 14:00 | 15:00 | 16:00 | 17:00 |
  | 끝 | 09:50 | 10:50 | 11:50 | 12:50 | 13:50 | 14:50 | 15:50 | 16:50 | 17:50 |

  - 교시 규칙이 고정이므로 운영자가 학기마다 입력하지 않고, 서비스에 미리 넣어 둡니다.
  - 쉬는 시간(예: 09:50~10:00)에는 다음 교시 기준으로 보여 줍니다.
  - **야간 수업은 지원하지 않습니다.** 학교 안내에는 10교시(~18:50)와 야간 수업(18:00~22:05)도 있지만, 이 서비스는 1~9교시(09:00~17:50)만 다룹니다. 18:00 이후에 열면 "18시 이후 시간대는 제공하지 않습니다"라고 안내합니다.
  - 9교시가 끝난 17:50~18:00 사이와 09:00 이전에 어떻게 보여 줄지는 `03_기능명세서.md`에서 정합니다.
- **강의실 목록**(건물·호실)은 시간표에 나오는 강의실로 만듭니다. 시간표에 한 번도 안 나오는 방은 수업용 강의실이 아닌 것으로 봅니다.
- **수용 인원**은 학교 홈페이지에 강의실별로 모여 있지 않습니다(2026-09 조사). 일부 단과대학 건물 소개 페이지에만 몇몇 강의실이 나옵니다(예: 사범대학1호관 제1합동강의실 120명, 사범대학2호관 제2합동강의실 80명). 그래서 **수강 정원으로 수용 인원을 추정**합니다.
  - 그 강의실에서 열리는 수업들의 수강 정원 중 **가장 큰 값**을 "약 N명(추정)"으로 보여 줍니다. 그만큼의 학생이 실제로 그 방에서 수업을 듣기 때문입니다.
  - 홈페이지에 수용 인원이 나온 강의실은 그 값을 우선 씁니다.
  - HWP 시간표에 **과목별 수강 정원(인원 제한) 칸이 있음**을 확인했습니다.
- 건물의 **층 구성**은 강의실 번호로 대부분 알 수 있습니다(예: 305호 → 3층). 번호로 알 수 없는 예외 강의실만 운영자가 층을 따로 입력합니다.
- 캠퍼스맵 위에서 **건물마다 누를 수 있는 영역**을 운영자가 한 번 정해 둡니다. 캠퍼스맵이 바뀌면 다시 맞춥니다.

### 7.3 학교와의 관계

- 시간표·폐강 교과목은 학교 홈페이지에 공개된 자료이므로, **화면에 출처를 밝히고** 씁니다. 예: "출처: 국립순천대학교 수업시간표(2026-2학기) · 폐강 교과목 안내"
- 교무학사과에 시간표 **엑셀 원본**을 받을 수 있는지 물어보면 HWP를 옮기는 수작업을 줄일 수 있습니다(선택 사항).
- 학사 시스템 연동·공개 시간표 자동 수집은 학교 허락을 받은 뒤 다음 단계에서 검토합니다.
- 나중에 **학교 공식 앱과 연동하거나 공식 앱에 편입**될 수 있습니다. 이때 쉽게 옮길 수 있도록, 학생 로그인·계정은 이번에 만들지 않습니다.

### 7.4 캠퍼스맵 관련

- 건물 고르기에는 외부 지도 서비스(카카오맵 등)를 쓰지 않고, **따로 준비한 캠퍼스맵**을 씁니다. (카카오맵 방식은 철회)
- **캠퍼스맵을 무엇으로 만들지는 나중에 정합니다(보류).** 후보는 학교 홈페이지의 캠퍼스맵 그림, 사진, 직접 만든 지도 등입니다. 04·목업 단계에서 정합니다. **(확인 필요)**
- 어느 것으로 만들든 캠퍼스맵은 **위에서 내려다본 지도 모양**으로 보이고, 아래 동작이 되어야 합니다.
  - 휴대폰: 한 손가락으로 끌어 옮기기, 두 손가락으로 확대·축소
  - PC: 마우스로 끌어 옮기기, 휠로 확대·축소
  - 건물 이름은 확대해도 읽을 수 있게 지도 위에 글자로 따로 올립니다.
- 지도 위에 건물마다 누를 수 있는 영역을 만들어, 건물을 누르면 **층별 안내도**로 넘어가게 합니다.
- 그림이나 사진을 쓰면 너무 크게 확대할 때 흐려질 수 있습니다. 확대할 수 있는 최대 크기는 캠퍼스맵을 정할 때 함께 정합니다(04·05).
- 외부 지도 서비스를 쓰지 않으므로 **사용료·사용량 한도 걱정이 없습니다.**
- **GPS로 "내 위치"를 표시하지 않습니다.** 학생이 건물을 직접 눌러 고릅니다.
- 학교 자료(그림·사진 등)를 쓰면 **화면에 출처를 밝힙니다.** 예: "캠퍼스맵 출처: 국립순천대학교"
- 캠퍼스맵의 건물 중 **강의실이 있는 건물만** 누를 수 있게 합니다(예: 학생생활관·체육관 등은 제외).

### 7.5 층별 안내도 관련

- 층별 안내도는 건물을 고르면 **층마다 강의실 호실과 비어 있는지**를 보여 주는 화면입니다. 그림 모양은 아래처럼 보류 중입니다.
- 층 구성은 강의실 번호로 정합니다(7.2 참고). 강의실이 하나도 없는 층은 보여 주지 않거나 "강의실 없음"으로 표시합니다(04에서 정함).
- **그림 모양은 나중에 다시 정합니다(보류).** 다시 짤 가능성이 높아, 화면을 만들 때(`04_화면설계서.md`·목업 단계) 다시 결정합니다. 후보는 다음과 같습니다.
  1. **강의실 배치 그림**: 층마다 강의실이 실제로 놓인 모양을 그림으로 보여 줌. 학교에 공개된 평면도가 없으므로 배치를 직접 그려야 함
  2. **실제 지도 참고**: 실제 지도를 참고해 건물 위치와 **위에서 본 건물 모양**을 그리고, 그 위에 강의실을 배치함(그릴 때 참고만 하며, 외부 지도 서비스를 화면에 넣는 것은 아님)
  3. **목록 모양**: 층을 위아래로 쌓고 층마다 강의실을 나열함(가장 간단한 대안)
- 어떤 방식이든 **"건물 → 층 → 빈 강의실"을 찾는 흐름은 같습니다.** 03 기능명세서는 이 흐름을 기준으로 쓰고, 그림 모양은 `04_화면설계서.md`·목업 단계에서 정합니다. **(확인 필요)**

### 7.6 기타 제약

- 이번에는 **PC 웹을 먼저** 만듭니다. PC 화면을 기준으로 설계하고, 휴대폰 브라우저에서도 깨지지 않게 합니다. 휴대폰 전용 화면·앱은 다음 단계에서 검토합니다.
- 예상 사용자는 약 7,000명이고 동시 접속은 적을 것으로 봅니다. 따라서 큰 서버는 필요 없을 것으로 보고, 규모는 `08_아키텍처_ADR.md`에서 정합니다.
- 학교 공식 앱과는 이번에 연동하지 않습니다.
- 기술스택(쓸 프로그램·도구)은 정하지 않았습니다. `08_아키텍처_ADR.md`에서 정합니다. **(확인 필요)**
- **학생 개인정보는 다루지 않습니다.** 학생 로그인·알림·즐겨찾기가 없어 서버에 학생 정보를 저장하지 않고, 위치 정보도 쓰지 않습니다. 관리자 계정·접속 기록 등 남은 보안 항목은 `09_보안_개인정보.md`에서 정합니다.
- 관리자 화면은 학생에게 숨기고 관리자 로그인으로 보호합니다. 관리자 계정을 어떻게 지킬지는 `09_보안_개인정보.md`에서 정합니다.
