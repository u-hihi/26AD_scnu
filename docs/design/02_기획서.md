## 1. 배경·목적

### 1.1 배경

- 순천대학교 학생은 수업 사이에 애매하게 빈 시간이 자주 생깁니다. 이 시간을 **공강**이라고 부릅니다.
- 공강에 공부하거나 쉴 곳으로 빈 강의실을 쓰고 싶어도, 어느 강의실이 비어 있는지 알기 어렵습니다.
- 지금은 건물을 돌아다니며 문을 열어 보거나, 시간표를 직접 뒤져 봐야 합니다.
- 학교 공식 시간표는 학기마다 공지사항에 HWP(한글 문서) 파일로 올라옵니다. 따로 "실시간 조회" 페이지(향림통시스템)도 있습니다.
- 하지만 이 자료들은 "지금 어느 강의실이 비었는지"를 한눈에 보여 주지 않습니다.

### 1.2 목적

- 서비스 이름은 **"순천대 공실 알리미"**(가칭: 임시로 정한 이름)입니다.
- 학생이 웹 브라우저(PC·휴대폰)로 **지금 비어 있는 강의실을 바로 찾게** 합니다.
- 원하는 날짜·교시를 골라, 건물마다 빈 강의실을 미리 볼 수 있게 합니다.
- 강의실의 수용 인원·다음 수업 시각을 함께 보여 줘서, 얼마나 오래 쓸 수 있는지 판단하게 돕습니다.

### 1.3 성공의 모습 (정성 목표)

- 학생은 **앞 수업이 끝난 건물이나 다음 수업이 있는 건물**을 기준으로 빈 강의실을 찾습니다. 멀리 이동하지 않고 그 건물 안에서 고르는 것이 보통입니다.
- 그래서 학생이 **날짜·교시 고르기 → 캠퍼스맵에서 건물 → 층별 안내도에서 공실** 순서로 헤매지 않고 찾을 수 있어야 합니다. 캠퍼스맵은 위에서 내려다본 지도 모양이며, 끌어 옮기고 확대해 건물을 누릅니다. 건물을 누르면 층별 안내도가 나오고, 층마다 고른 날짜·교시의 공실 / 수업중이 보입니다(안내도 모양은 7.5 참고).
- 학생이 앱을 설치하지 않고 웹 브라우저로 쓸 수 있습니다. **PC 화면을 기준**으로 만들되, 휴대폰 브라우저로 열어도 깨지지 않습니다.
- 사용자가 화면에서 "이 정보가 언제 기준인지"를 항상 알 수 있습니다.
- 숫자로 된 목표(화면이 뜨는 시간 등)는 `03_기능명세서.md`의 NFR·SLO(비기능 요구·목표 수준)에 **제안값**으로 적었습니다. 사용자가 확인한 뒤 확정합니다.

## 2. 대상·사용자

| 구분 | 누구 | 하는 일 | 주로 쓰는 곳 |
|---|---|---|---|
| 학생 사용자 | 순천대학교 학생 | 날짜·교시 고르기, 건물·층별 공실 보기, 강의실 상세 보기, 공지 보기, 문의·신고 보내기 | 학생 화면(웹) |
| 관리자 | **1명** | 시간표·폐강 교과목 파일 반영, 학기·건물·층·강의실·캠퍼스맵·공휴일 정보 관리, 건물·층·강의실 사용 불가 설정, 공지·배너·팝업 관리, 문의·신고 처리, 방문 통계 보기, 바꾼 내용 공개하기([공개하기]) | 관리자 화면(PC) |

- 학생 화면은 **PC 웹을 먼저** 만듭니다. 다만 공강에 이동하면서 휴대폰으로 열 수도 있으므로, 휴대폰 브라우저에서도 화면이 깨지지 않게 합니다(반응형).
- **관리자 화면은 PC만 지원합니다.** 휴대폰 화면은 맞추지 않습니다(3.2).
- 서비스는 **학생 화면·관리자 화면·서버·데이터베이스**로 이루어집니다(5장). 서버는 화면의 요청을 받아 처리하는 프로그램이고, 직접 만듭니다. 데이터베이스는 데이터를 정리해 저장해 두는 곳입니다.
- 이번에는 이 구성을 모두 **관리자 PC(로컬 PC)**에서 실행해 시연합니다. 시연은 만든 서비스를 실행해 동작을 보여 주는 것입니다. 학생 대상 공개(인터넷에 올리기)는 하지 않습니다(3.2).
- **학생 로그인은 넣지 않습니다.** 나중에 학교 공식 앱과 연동하거나 공식 앱에 편입될 수 있어, 계정 기능은 그때 학교 계정에 맞추는 편이 낫습니다.
- **관리자는 관리자 화면에 아이디·비밀번호로 로그인합니다.** 비밀번호는 바꿀 수 있지만, 계정 추가·삭제와 역할 나누기는 두지 않습니다. 관리 일은 모두 관리자 화면에서 합니다.
- **서비스가 저장하는 학생 정보는 문의 이메일뿐입니다.** 이메일은 문의할 때만 받습니다(선택 입력·동의). 이 이메일은 처리 후 지웁니다(7.7).
- 방문 통계에 쓰는 식별값(같은 브라우저인지 알아보려고 브라우저에 남기는 작은 기록. 예: 쿠키)을 어떻게 안내하고 동의받을지는 `09_보안_개인정보.md`에서 정합니다.
- 예상 사용자는 **약 7,000명**입니다. 모두가 한꺼번에 접속하지는 않을 것으로 봅니다(동시 접속은 적음).

### 2.1 대표 사용 장면

1. 2교시 수업이 공과대학 1호관에서 끝났고, 4교시까지 1시간이 빕니다. 학생이 서비스를 열면 오늘 날짜·지금 교시가 이미 골라져 있습니다. 캠퍼스맵을 끌고 확대해 **공과대학 1호관(D2)을 누르면** 층별 안내도가 나옵니다. 층을 스크롤하다 보니 3층에 공실이 있습니다(예시 장면).
2. 학생이 한 강의실을 누르면 "약 30명(추정) · 다음 수업 13:00 시작"이 보입니다.
3. 내일 오후 조별 모임 장소를 찾으려고, 필터 달력에서 **내일 날짜**를 고르고 그 밑에서 **5교시**를 고른 뒤 공과대학 1호관을 누릅니다.

> `idea.md`의 기능 "지금 빈 강의실 목록"은 기능 1·2·3(날짜·교시 → 캠퍼스맵 → 건물 → 층 → 공실)으로 구체화했습니다.

이 기능들을 돌리기 위해 함께 필요한 것:

- **서버·데이터베이스**: 서버를 직접 만듭니다. 학생 화면과 관리자 화면은 API(화면과 서버가 데이터를 주고받는 창구)로 서버와 데이터를 주고받습니다. 데이터는 데이터베이스에 저장합니다. 프로그래밍 언어·데이터베이스 종류·서버 프레임워크(서버 프로그램을 만들 때 쓰는 기본 틀)는 `08_아키텍처_ADR.md`에서 정합니다.
- **실행 장소**: 학생 화면·관리자 화면·서버·데이터베이스를 모두 관리자 PC(로컬 PC)에서 실행해 시연합니다. 학생 대상 공개는 하지 않습니다(3.2).
- **웹(PC 우선)**: 브라우저에서 쓰는 웹 화면입니다. 설치하는 앱이 아닙니다. 학생 화면은 PC 화면을 기준으로 하고, 휴대폰 브라우저에서도 열립니다. 관리자 화면은 PC만 지원합니다.
- **관리자 기능(관리자 화면에서 함)**: 아래 표와 같습니다. `03_기능명세서.md`에서 "관리자 기능"으로 따로 번호를 붙입니다. 세부 규칙(검사 규칙, 수용 인원 최댓값 규칙, 사라진/다시 추가된 강의실 알림, 관리자 값 우선 등)은 7장을 따릅니다. 내용·설정 값은 관리자 화면에서 관리합니다. 보안 관련 시간·횟수만 예외로 서버 설정 파일(서버가 읽는 설정 값을 적어 둔 파일)에서 정합니다(7.7).

### 3.2 이번에 안 할 것 (범위 밖)

- 학교 공식 앱과 연동하거나, 공식 앱에 기능을 추가하는 것 (나중에 연동·편입 가능성은 열어 둠)
- 휴대폰 전용 화면(모바일 버전)과 안드로이드·iOS(아이폰 운영체제) 앱 (웹을 먼저 만든 뒤 검토)
- 학생 로그인·계정 기능 (공식 앱 연동 시 학교 계정에 맞춰 검토)
- **학생 대상 공개**(서비스를 인터넷에 올려 누구나 접속하게 하는 것) (학생 화면·관리자 화면·서버·데이터베이스는 관리자 PC에서 실행해 시연함)
- **관리자 화면 휴대폰 지원** (관리자 화면은 PC만 지원함. 학생 화면은 휴대폰 브라우저에서도 깨지지 않게 함)
- **자동 새로고침** (화면을 켜 둔 채 교시가 바뀌어도 자동으로 바꾸지 않음. 학생이 초기화 버튼을 누름)
- **접근성 기능**(키보드만으로 조작하기 등) (나중에 추가. 지금은 마우스 조작으로 충분하다고 봄)
- 교시 범위 검색(예: 3~5교시)과 "전체 건물" 검색 (교시는 하나만, 건물도 하나만 고름)
- 주말·공휴일 운영 (달력에서 주말·공휴일 날짜는 고를 수 없음. 오늘이 주말·공휴일이면 건물을 누를 때 "운영하지 않는 날입니다" 같은 문구만 보여 줌)
- 학사 시스템과의 자동 연동 (학교 승인 필요, 다음 단계 후보)
- 공개 시간표 페이지 자동 수집(크롤링: 프로그램이 웹 페이지 내용을 자동으로 긁어 오는 것) (학교 허락 필요, 다음 단계 후보)
- 휴강·보강·시험 일정 (알 수 없어 반영하지 않음. 특히 휴강은 예고 없이 생김)
- 10교시·야간 수업 시간대(18:00 이후) (지원하지 않음)
- 외부 지도 서비스(카카오맵 등)·GPS(위성으로 현재 위치를 알아내는 기능) 현재 위치 표시 (캠퍼스맵을 따로 준비해 쓰므로 제외)
- 강의실 콘센트 정보
- 알림(웹 푸시: 브라우저를 통해 PC·휴대폰에 알림을 보내는 기능)·즐겨찾기·공강 시간 입력 (수업은 매주 같은 시간·같은 장소에서 열려 알림의 필요성이 낮으므로 제외)

| [공개하기] | 관리자 화면에서 저장한 변경을 학생 화면에 내보내는 버튼. 학생 화면에 보이는 모든 정보·설정 값이 대상입니다. 예: 시간표·폐강 교과목·건물·층·강의실(수용 인원)·학기 정보·캠퍼스맵·교시 시각표·출처·안내 문구·신고 종류 선택지·건물 목록 정렬 순서·캠퍼스맵 최대 확대 크기·공지·배너·팝업·공휴일 목록·사용 불가 설정. 누르기 전에는 학생 화면에 앞서 공개한 내용이 그대로 보입니다. 누른 시각이 기준 표시의 업데이트 시각이 됩니다(7.7). |
| 시간표 파일 | 관리자가 관리자 화면에서 올리는 한 학기 분량의 엑셀/CSV 파일. 학교가 HWP로 공지한 시간표를 우리가 정한 양식으로 옮긴 것 |
| CSV | 쉼표로 칸을 나눈 단순한 표 파일 형식. 엑셀에서 열고 저장할 수 있음 |
| xlsx | 엑셀 파일 형식. 학교가 폐강 교과목 목록을 이 형식으로 제공함 |
| 폐강 교과목 파일 | 학교가 수강정정 뒤 확정하는 폐강 수업 목록. 관리자가 시간표 파일과 함께 관리자 화면에서 올립니다. |
| 대시보드 | 관리자가 방문자 수·건물 조회수·처리할 문의·신고를 모아 보는 관리자 화면. 새 오류 건수도 보이고, 누르면 오류 기록으로 이동합니다(7.7). |
| 방문 통계 | 일일 방문자 수와 건물 조회수(건물을 누른 횟수). 서버가 직접 세어 데이터베이스에 저장합니다. 누구인지는 저장하지 않습니다. |
| 오류 기록 | 서버가 처리하지 못한 일을 실패 이유와 함께 남긴 기록. 관리자가 관리자 화면의 "오류 기록" 메뉴에서 봅니다. 이 메뉴는 대시보드와 따로 둡니다(7.7). |
| [다시 시도] | 학생 화면이 서버에서 정보를 받지 못했을 때 보이는 단추. 누르면 다시 불러옵니다. |

| 처리 상태 | 문의·신고를 처리했는지 나타내는 표시. 관리자가 관리자 화면의 목록에서 바꿉니다. |
| 문의 답장 메일 | 관리자가 관리자 화면에서 쓴 답장을 서버가 학생 이메일로 보내는 것. 보내는 방식은 `08_아키텍처_ADR.md`에서 정합니다. |
| 출처 문구 | 시간표·폐강 교과목·캠퍼스맵 자료의 출처를 화면에 밝히는 글. 관리자가 관리자 화면에서 관리합니다(7.3). |
| 화면 안내 문구 | 학생 화면에 보이는 안내 글. 예: "운영하지 않는 날입니다", "현재 학기 수업 기간이 아닙니다". 관리자가 관리자 화면에서 고칩니다(7.7). |
| 신고 종류 선택지 | 신고 화면에서 학생이 고르는 신고 종류 목록. 관리자가 관리자 화면에서 고치며, 처음 값은 `03_기능명세서.md` FR-011의 선택지입니다. |
| 사용 불가 설정 | 공사나 갑작스러운 사정으로 건물·층·강의실을 쓸 수 없을 때 관리자가 관리자 화면에서 하는 설정. 사용 불가로 설정된 강의실은 공실로 보이지 않습니다. [공개하기]를 눌러야 학생 화면에 보입니다(7.7). |
| 공지사항·배너·팝업 | 공지사항은 알리는 글, 배너는 화면 한쪽에 띠 모양으로 보이는 안내, 팝업은 화면 위에 따로 뜨는 안내 창입니다. |
| 캠퍼스맵 | 이 서비스에서 보여 주는 학교 지도. 무엇으로 만들지(학교 배치도 그림·사진·직접 제작 등)는 나중에 정합니다(7.4). 위에서 내려다본 지도 모양으로 보이고, 끌어서 옮기고 확대·축소할 수 있으며, 건물 자리를 누를 수 있습니다. |
| 확대·축소·끌어 옮기기 | 휴대폰에서 두 손가락을 벌리거나(확대) 오므리고(축소), 한 손가락으로 끌어 보는 곳을 옮기는 동작. PC에서는 마우스 휠과 끌기로 합니다. |

## 5. 시스템 구성 개요

서비스는 **학생 화면·관리자 화면·서버·데이터베이스**로 이루어집니다. 서버는 직접 만듭니다. 학생 화면과 관리자 화면은 API로 서버와 데이터를 주고받습니다. 서버는 데이터를 데이터베이스에 저장합니다. 관리 일은 모두 관리자 화면에서 합니다.

이번에는 이 네 가지를 모두 **관리자 PC(로컬 PC)** 안에서 실행해 시연합니다. 학생 대상 공개는 하지 않습니다(3.2·7.7). 공공 공휴일 정보 API만 관리자 PC 밖에 있고, 서버가 인터넷으로 받아 옵니다(7.6). 아래 그림은 이 모습입니다.

```
[관리자 PC(로컬 PC)] ── 학생 화면·관리자 화면·서버·데이터베이스는 모두 이 컴퓨터 안에서 실행됩니다.

  [브라우저: 학생 화면] (로그인 없음)
     |-- 시간표·강의실·캠퍼스맵·사용 불가 정보 받기 --> [서버]
     |-- 공지·배너·팝업·공휴일 받기 --------> [서버]
     |-- 지금 시각(한국 시간) 받기 ---------> [서버]
     |-- 문의·신고 보내기 -------------------> [서버]
     |-- 방문·건물 누름 알리기 --------------> [서버]

  [브라우저: 관리자 화면] (아이디·비밀번호로 로그인, PC만)
     |-- 시간표·폐강 파일 올리기 ------------> [서버] (검사·변환)
     |-- 학기·교시 시각표·건물·층·강의실·캠퍼스맵 입력 --> [서버]
     |-- 출처·안내 문구·신고 종류·건물 정렬 순서·최대 확대 크기 입력 --> [서버]
     |-- [공개하기] 누르기 ------------------> [서버]
     |-- 공지·배너·팝업·공휴일·사용 불가 설정 저장 --> [서버]
     |-- [공휴일 불러오기]·인증키 입력 ------> [서버]
     |-- 문의·신고 처리, 문의 답장 쓰기 -----> [서버]
     |-- 대시보드(방문 통계)·오류 기록 보기 --> [서버]
     |-- 비밀번호 바꾸기 --------------------> [서버]

  [서버] <-------- 저장·읽기 --------> [데이터베이스]
     |-- 문의 답장 메일 보내기 --------------> [메일 보내기] (방식은 08에서 정함)
     |-- 공휴일 받아 오기 -------------------> [공공 공휴일 정보 API] (관리자 PC 밖, 인터넷)
```

| 구성 요소 | 쉬운 설명 |
|---|---|
| 학생 화면 | 학생이 웹 브라우저로 보는 화면입니다(PC 기준, 휴대폰 브라우저에서도 깨지지 않음). 로그인 없이 씁니다. 날짜·교시 필터, 초기화 버튼, 캠퍼스맵, 층별 안내도, 강의실 상세, 공지·배너·팝업, 문의 화면·신고 화면이 들어갑니다. 필요한 정보와 지금 시각(한국 시간)은 API로 서버에서 받습니다. |
| └ 캠퍼스맵 (학생 화면의 일부) | 캠퍼스맵을 위에서 내려다본 지도 모양으로 띄워 끌어 옮기기·확대·축소가 되게 하고, 건물 자리를 누르면 그 건물의 층별 안내도로 들어갑니다. 외부 지도 서비스는 쓰지 않습니다. |

| 서버 | 직접 만드는 프로그램입니다. 학생 화면·관리자 화면의 요청을 API로 받아 처리합니다. 관리자 로그인을 확인합니다. 시간표·폐강 교과목 파일을 검사하고 변환해 데이터베이스에 저장합니다. 공공 공휴일 정보 API에서 공휴일을 받아 오고, 학기를 반영할 때 빠진 연도를 경고합니다(7.6). 학생 화면에 지금 시각(한국 시간)을 알려 줍니다. 방문자 수·건물 조회수를 셉니다. 관리자가 쓴 문의 답장을 메일로 보냅니다. 처리하지 못한 일은 실패 이유와 함께 기록합니다(7.7). |
| 데이터베이스 | 서버가 데이터를 저장하는 곳입니다. 학기 정보(이름·기간·업데이트 시각), 교시 시각표, 수업 시간(강의실·요일·교시), 폐강 수업, 건물·층·강의실(수용 인원), 캠퍼스맵·건물 영역, 강의실 코드와 건물을 짝짓는 표, 출처·안내 문구, 신고 종류 선택지, 건물 목록 정렬 순서, 캠퍼스맵 최대 확대 크기, 공지·배너·팝업, 공휴일 목록, 사용 불가 설정, 문의·신고와 처리 상태, 방문 통계를 담습니다. 학생에 관한 정보는 문의 이메일만 담고, 처리 후 지웁니다. 표 구성은 `06_데이터모델_ERD.md`에서, 종류는 `08_아키텍처_ADR.md`에서 정합니다. |
| 메일 보내기 | 문의 답장을 학생 이메일로 보내는 부분입니다. 실제 메일 서비스를 쓸지, 관리자 PC 안에서 보낸 메일을 받아 보여 주는 도구를 쓸지는 `08_아키텍처_ADR.md`에서 정합니다. |
| 공공 공휴일 정보 API | 공휴일 정보를 내주는 공공 창구입니다. 관리자 PC 밖에 있고, 서버가 인터넷으로 받아 옵니다. 어떤 API를 쓸지는 `08_아키텍처_ADR.md`에서 정합니다. 무료이고 인증키 신청이 필요한 공공 API가 후보입니다. |

### 5.1 데이터가 흐르는 순서

**시간표·강의실 정보**

1. 학교가 학기 시간표를 HWP 파일로 공지합니다. 폐강 교과목은 학교가 xlsx 파일로 줍니다.
2. 관리자가 시간표 내용을 **우리가 정한 엑셀/CSV 양식**으로 옮깁니다(수작업).
3. 관리자가 관리자 화면에 로그인해, 시간표 파일과 최종 폐강 교과목 파일을 올립니다. 학기 이름·시작일·종료일, 교시 시각표, 건물·층·수용 인원, 캠퍼스맵, 그 밖의 학생 화면 설정 값(출처·안내 문구 등)은 필요할 때 관리자 화면에서 고칩니다.
4. 서버가 파일을 검사합니다. 오류가 있으면 오류 줄 번호와 이유를 관리자 화면에 목록으로 보여 주고, 고쳐서 다시 올릴 때까지 반영하지 않습니다. 공휴일 목록도 확인해, 학기가 걸친 연도의 공휴일이 없으면 경고합니다(7.6).
5. 검사를 통과하면 서버가 **폐강된 수업을 공실 판정에서 빼고** 데이터베이스에 저장합니다. 같은 학기면 수업 시간 데이터를 덮어쓰고, 관리자가 직접 입력한 층·수용 인원은 남깁니다. 새 학기면 지난 학기의 수업 시간 데이터만 지웁니다.
6. 관리자가 모든 수정을 마친 뒤 관리자 화면에서 **[공개하기]**를 누릅니다. 그때부터 학생 화면에 새 정보가 보입니다. 누른 시각이 기준 표시의 업데이트 시각이 됩니다(7.1-5).
7. 학생이 학생 화면을 열면, 학생 화면이 서버에서 공개된 정보와 지금 시각(한국 시간)을 받습니다. 필터에는 오늘 날짜와 지금 교시가 골라져 있습니다(7.6).
8. 학생이 날짜·교시를 고르고 캠퍼스맵에서 건물을 누르면(또는 건물 목록에서 고르면), 학생 화면이 서버에서 받은 정보로 공실 / 수업중을 계산해 층별 안내도에 보여 줍니다. 사용 불가로 설정된 강의실은 공실로 보이지 않습니다(7.7).

**공지·공휴일·사용 불가·문의·통계·오류 기록**

9. 관리자가 관리자 화면에서 공지사항·배너·팝업과 사용 불가 설정을 저장합니다. 공휴일은 [공휴일 불러오기] → 받아 온 목록 확인 → [저장] 순서로 넣고, 학교 휴업일 등은 관리자가 추가합니다(7.6). 이 변경도 [공개하기]를 눌러야 학생 화면에 쓰입니다(5.1-6). 학생 화면은 서버에서 공지·배너·팝업을 받아 보여 주고, 공휴일 목록을 받아 달력에 씁니다.
10. 학생이 문의하기·신고하기를 누르면 사이트 안의 문의 화면·신고 화면이 열립니다. 보낸 내용은 서버가 데이터베이스에 저장합니다. 관리자는 관리자 화면의 목록에서 처리 상태를 바꿔 가며 처리합니다.
11. 관리자가 관리자 화면에서 문의 답장을 쓰면, 서버가 학생이 적은 이메일로 메일을 보냅니다(보내는 방식은 08에서 정함). 신고에는 답장하지 않습니다.
12. 학생이 학생 화면을 열거나 건물을 누르면 서버가 셉니다(7.7). 관리자는 이 숫자를 관리자 화면의 대시보드에서 봅니다.
13. 서버가 처리하지 못한 일이 있으면 실패 이유와 함께 기록합니다. 관리자는 관리자 화면의 "오류 기록" 메뉴에서 이 기록을 봅니다. 학생 화면이 서버에서 정보를 받지 못하면, 학생 화면에는 이유 없이 불러오기 실패 안내와 [다시 시도] 단추만 보입니다(7.7).

> 건물 고르기는 외부 지도 서비스 대신 **따로 준비한 캠퍼스맵**을 쓰기로 정했습니다. 캠퍼스맵을 무엇으로 만들지는 나중에 정합니다(7.4). 프로그래밍 언어, 데이터베이스 종류, 서버 프레임워크, 메일 보내는 방식, 공공 공휴일 정보 API 같은 기술 제품은 이 문서에서 고르지 않습니다. `08_아키텍처_ADR.md`에서 정하고, 캠퍼스맵 선택을 포함해 선택 이유를 ADR(설계 결정 기록)로 남깁니다.

## 7. 가정·제약

### 7.1 시간표 데이터 관련 (결정 사항에서 나온 제약)

1. **학기 단위 파일로 반영한다.** 학교 학사 시스템의 공개 API(프로그램끼리 데이터를 주고받는 창구)를 찾지 못했습니다. 그래서 관리자가 한 학기 분량의 엑셀/CSV 파일을 관리자 화면에서 올려 반영하는 방식으로 정했습니다.
2. **한 학기 분량만 다룬다.** 학교에서 받을 수 있는 시간표는 한 학기 분량뿐입니다. 빈 강의실 찾기에는 이번 학기 정보만 있으면 됩니다.
3. **학기마다 새로 반영하고, 지난 학기 수업 시간은 지운다.** 학기마다(2월·8월쯤) 새 파일을 반영합니다. 새 학기를 반영하면 지난 학기의 **수업 시간 데이터만 지웁니다.** 건물·강의실·층·수용 인원 정보는 남깁니다. 공실은 **매 학기 그 학기 시간표의 수업 시간으로만** 판단합니다. 지난 학기에만 나오고 새 학기 시간표에 없는 강의실도 목록에 남으며, 수업이 없으므로 공실로 보입니다(숨기거나 따로 표시하지 않음).
4. **정정 기간에는 다시 반영한다.** 수강정정이 끝날 때까지 시간표가 수시로 바뀝니다. 같은 학기 파일을 다시 반영하면 수업 시간 데이터를 덮어씁니다. 관리자가 직접 입력한 층·수용 인원은 남깁니다. 앞 파일에만 있던 강의실도 목록에 남깁니다. 서버가 "이번 파일에서 사라진 강의실" 목록을 관리자 화면에 알려 주므로, 오타 코드로 잘못 들어간 강의실이면 관리자가 지울 수 있습니다. 지운 강의실이 다음 파일에 다시 나오면 목록에 다시 넣습니다(7.2). 폐강 파일만 바꿔 다시 반영해도 같습니다.
5. **화면에 기준을 표시한다.** "2026-2학기 시간표 기준 · 9/15 업데이트"처럼 보여 줘서 정보가 최신인지 알게 합니다. 업데이트 날짜는 **관리자가 모든 수정을 마치고 관리자 화면에서 [공개하기]를 누른 시각**을 기준으로 합니다. 모든 수정은 학생 화면에 보이는 정보·설정 값(7.7)을 고친 것입니다. 시간표·폐강 교과목·캠퍼스맵·강의실 정보뿐 아니라 공지·배너·팝업, 공휴일 목록, 사용 불가 설정도 포함됩니다. 무엇을 공개했든 [공개하기]를 누른 시각이 업데이트 날짜가 됩니다. 학교가 새 자료를 공지해도, 관리자가 반영하고 [공개하기]를 누를 때까지는 기존 정보를 그대로 보여 줍니다.
6. **학기가 아닌 기간을 처리한다.** 관리자가 학기 시작일·종료일을 관리자 화면에서 입력합니다. 방학·계절학기에는 "현재 학기 수업 기간이 아닙니다"라고 안내합니다.
7. **최종 폐강 교과목을 반영한다.** 관리자가 시간표 파일과 함께 최종 폐강 교과목 파일을 반영합니다. 폐강된 수업이 잡혀 있던 시간의 강의실은 공실로 보여 줍니다. 폐강 파일에만 나오고 본 시간표에는 없는 정보(강의실·정원 등)는 강의실 목록에 추가합니다. 폐강된 수업이므로 수업 시간은 넣지 않습니다.
8. **휴강·보강·시험 일정은 알 수 없다.** 이 일정은 시간표에 나오지 않고, 특히 휴강은 예고 없이 생깁니다. 그래서 반영하지 않고, 화면에 "휴강·보강·시험 일정은 반영되지 않습니다"라고 짧게 안내합니다.

### 7.2 관리 수작업 관련

- 관리자는 **1명**입니다.
- **수업 시간표는 HWP 파일**입니다. HWP는 프로그램이 자동으로 읽기 어려워서, 관리자가 이 내용을 **우리가 정한 엑셀/CSV 양식으로 옮기는 수작업**이 필요합니다.
- **폐강 교과목은 xlsx(엑셀) 파일**입니다. 학교 파일을 그대로 관리자 화면에서 올립니다. 학교 파일의 칸 구성이 학기마다 같은지는 파일을 받아 확인합니다.
- 옮기는 과정에서 실수가 생길 수 있습니다. 그래서 서버가 파일을 검사합니다. 오류 줄 번호와 이유를 관리자 화면에 보여 주고, 고칠 때까지 반영하지 않습니다. 같은 강의실·요일·교시에 수업이 겹치면 관리자에게 경고로 알립니다(03 FR-024).
- 시간표 엑셀/CSV 양식(어떤 칸을 둘지)은 03·06에서 정합니다. 폐강 교과목 파일과 **같은 과목을 맞춰 볼 수 있는 칸**(예: 과목 코드·분반)이 꼭 있어야 합니다.
- **교시 시각표(확정)**: 1교시 09:00 시작, 매 교시 정시 시작, 50분 수업·10분 쉬는 시간, 1~9교시.

  | 교시 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
  |---|---|---|---|---|---|---|---|---|---|
  | 시작 | 09:00 | 10:00 | 11:00 | 12:00 | 13:00 | 14:00 | 15:00 | 16:00 | 17:00 |
  | 끝 | 09:50 | 10:50 | 11:50 | 12:50 | 13:50 | 14:50 | 15:50 | 16:50 | 17:50 |

  - 교시 시각표는 관리자가 관리자 화면에서 관리합니다. 위 표가 처음 값이며, 학기마다 다시 입력하지 않아도 됩니다.
  - 쉬는 시간(예: 09:50~10:00)에는 다음 교시 기준으로 보여 줍니다.
  - **야간 수업은 지원하지 않습니다.** 학교 안내에는 10교시(~18:50)와 야간 수업(18:00~22:05)도 있지만, 이 서비스는 1~9교시(09:00~17:50)만 다룹니다. 필터에서도 1~9교시만 고를 수 있습니다.
  - 지금이 수업 시간(1~9교시) 밖이면(09:00 이전, 17:50 이후), 교시를 직접 고르라고 안내합니다(7.6).
- **강의실 목록**(건물·호실)은 시간표에 나오는 강의실로 만듭니다. 폐강 파일에만 나오는 강의실도 추가합니다(7.1-7). 시간표·폐강 파일에 한 번도 안 나오는 방은 수업용 강의실이 아닌 것으로 봅니다.
  - 관리자가 지운 강의실(7.1-4)이 다음에 반영하는 시간표·폐강 파일에 다시 나오면, 목록에 다시 넣습니다. 새 파일에 나왔다면 실제로 쓰는 강의실이기 때문입니다. 이때 서버가 "다시 추가된 강의실" 목록을 관리자 화면에 알려 줍니다.
    - 다시 넣을 때는 보관해 둔 값(관리자가 전에 적은 층·수용 인원, 지난 학기까지의 최댓값)을 되살립니다. 관리자가 적은 값이 우선이라는 규칙은 그대로입니다.
- **강의실 코드**: 시간표에는 강의실이 "A18101"처럼 코드로 나옵니다. 코드와 건물을 짝짓는 표는 관리자가 관리자 화면에서 관리합니다(3.1 FR-028). 호실 번호로 층을 정하는 규칙은 처리 규칙이라 그대로 둡니다. 짝짓는 표의 처음 내용(코드를 건물·호실과 짝짓는 방법)은 사용자가 나중에 알려 줍니다. **(확인 필요)**
- **건물 이름 표시**: 화면에는 "공과대학 1호관(D2)"처럼 건물 이름 뒤에 캠퍼스맵의 건물 번호를 붙입니다.
- **수용 인원**은 학교 홈페이지에 강의실별로 모여 있지 않습니다(2026-09 조사). 일부 단과대학 건물 소개 페이지에만 몇몇 강의실이 나옵니다(예: 사범대학1호관 제1합동강의실 120명, 사범대학2호관 제2합동강의실 80명). 그래서 **수강 정원으로 수용 인원을 추정**합니다.
  - **지금까지 반영한 모든 학기**에서 그 강의실에 잡힌 수업들의 수강 정원 중 **가장 큰 값**을 "약 N명(추정)"으로 보여 줍니다. 그만큼의 학생이 그 방에서 수업을 듣도록 잡혔기 때문입니다.
  - 새 학기를 반영할 때는 남겨 둔 값과 새 학기 수강 정원 중 큰 값을 남깁니다.
  - 같은 학기 파일을 다시 반영하면(예: 수강정정 기간) 이번 학기 최댓값은 새 파일로 다시 계산하고, 지난 학기까지의 최댓값과 비교해 큰 값을 씁니다. 앞서 반영한 같은 학기 값은 남기지 않습니다. 폐강 파일만 바꿔 다시 반영해도 같은 규칙으로 다시 계산합니다.
  - 폐강 수업의 수강 정원도 계산에 넣습니다. 본 시간표에도 나오는 강의실과 폐강 파일에만 나오는 강의실에 똑같이 적용합니다.
  - 홈페이지에 수용 인원이 나온 강의실은 관리자가 적은 그 값을 항상 우선 씁니다.
  - 홈페이지 값을 "(추정)" 없이 보일지는 사용자가 올려 줄 파일을 보고 정합니다. **(확인 필요)**
  - HWP 시간표에 **과목별 수강 정원(인원 제한) 칸이 있음**을 확인했습니다.
- 건물의 **층 구성**은 강의실 번호로 대부분 알 수 있습니다(예: 305호 → 3층). 번호로 알 수 없는 예외 강의실만 관리자가 층을 따로 입력합니다. 층을 끝내 알 수 없는 강의실을 화면에 어떻게 보일지는 사용자가 보고 판단합니다. **(확인 필요 — 사용자 판단)**
- 캠퍼스맵 위에서 **건물마다 누를 수 있는 영역**을 관리자가 한 번 정해 둡니다. 캠퍼스맵이 바뀌면 다시 맞춥니다.

### 7.3 학교와의 관계

- 시간표·폐강 교과목은 학교 홈페이지에 공개된 자료이므로, **화면에 출처를 밝히고** 씁니다. 예: "출처: 국립순천대학교 수업시간표(2026-2학기) · 폐강 교과목 안내". 출처 문구는 관리자가 관리자 화면에서 적고 고칩니다.
- 교무학사과에 시간표 **엑셀 원본**을 받을 수 있는지 물어보면 HWP를 옮기는 수작업을 줄일 수 있습니다(선택 사항).
- 학사 시스템 연동·공개 시간표 자동 수집은 학교 허락을 받은 뒤 다음 단계에서 검토합니다.
- 나중에 **학교 공식 앱과 연동하거나 공식 앱에 편입**될 수 있습니다. 이때 쉽게 옮길 수 있도록, 학생 로그인·계정은 이번에 만들지 않습니다.

### 7.4 캠퍼스맵 관련

- 건물 고르기에는 외부 지도 서비스(카카오맵 등)를 쓰지 않고, **따로 준비한 캠퍼스맵**을 씁니다. (카카오맵 방식은 철회)
- **캠퍼스맵을 무엇으로 만들지는 나중에 정합니다(보류).** 후보는 학교 홈페이지의 캠퍼스맵 그림, 사진, 직접 만든 지도 등입니다. 04·목업 단계에서 정합니다.
- 어느 것으로 만들든 캠퍼스맵은 **위에서 내려다본 지도 모양**으로 보이고, 아래 동작이 되어야 합니다.
  - 휴대폰: 한 손가락으로 끌어 옮기기, 두 손가락으로 확대·축소
  - PC: 마우스로 끌어 옮기기, 휠로 확대·축소
  - 건물 이름은 확대해도 읽을 수 있게 지도 위에 글자로 따로 올립니다.
- 지도 위에 건물마다 누를 수 있는 영역을 만들어, 건물을 누르면 **층별 안내도**로 넘어가게 합니다.
- 캠퍼스맵 관리(캠퍼스맵 그림 교체, 건물 영역 설정)는 **관리자 기능**입니다. 관리자 화면에서 하고, 저장한 뒤 [공개하기]를 눌러야 학생 화면에 보입니다.
- 그림이나 사진을 쓰면 너무 크게 확대할 때 흐려질 수 있습니다. 확대할 수 있는 최대 크기는 관리자가 관리자 화면에서 정합니다. 처음 값은 04·05에서 정합니다.
- 외부 지도 서비스를 쓰지 않으므로 **사용료·사용량 한도 걱정이 없습니다.**
- **GPS로 "내 위치"를 표시하지 않습니다.** 학생이 건물을 직접 눌러 고릅니다.
- 학교 자료(그림·사진 등)를 쓰면 **화면에 출처를 밝힙니다.** 예: "캠퍼스맵 출처: 국립순천대학교". 이 출처 문구도 관리자가 관리합니다(7.3).
- 캠퍼스맵의 건물 중 **강의실이 있는 건물만** 누를 수 있게 합니다(예: 학생생활관·체육관 등은 제외).
- 건물 목록의 **정렬 순서는 관리자가 관리자 화면에서 정합니다.** 처음 값은 04·05에서 정합니다. 후보로 "캠퍼스맵 건물 번호(D2 등) 순"이 있습니다.

### 7.5 층별 안내도 관련

- 층별 안내도는 건물을 고르면 **층마다 강의실 호실과 공실 / 수업중**을 보여 주는 화면입니다. 학생은 층별로 스크롤하며 봅니다. 그림 모양은 아래처럼 보류 중입니다.
- 층 구성은 강의실 번호로 정합니다(7.2 참고). 강의실이 하나도 없는 층은 보여 주지 않거나 "강의실 없음"으로 표시합니다(04에서 정함).
- **그림 모양은 나중에 다시 정합니다(보류).** 다시 짤 가능성이 높아, 화면을 만들 때(`04_화면설계서.md`·목업 단계) 다시 결정합니다. 후보는 다음과 같습니다.
  1. **강의실 배치 그림**: 층마다 강의실이 실제로 놓인 모양을 그림으로 보여 줌. 학교에 공개된 평면도가 없으므로 배치를 직접 그려야 함
  2. **실제 지도 참고**: 실제 지도를 참고해 건물 위치와 **위에서 본 건물 모양**을 그리고, 그 위에 강의실을 배치함(그릴 때 참고만 하며, 외부 지도 서비스를 화면에 넣는 것은 아님)
  3. **목록 모양**: 층을 위아래로 쌓고 층마다 강의실을 나열함(가장 간단한 대안)
- **공실 / 수업중을 어떤 모양으로 보여 줄지도 보류**입니다. 사용자가 목업을 보고 정합니다.
- 어떤 방식이든 **"날짜·교시 → 건물 → 층 → 공실"을 찾는 흐름은 같습니다(확정).** 03 기능명세서는 이 흐름을 기준으로 씁니다.
- 그림 모양은 `04_화면설계서.md`·목업 단계에서 정합니다(보류).

### 7.6 시간 기준·운영일 관련

- **시간 기준은 서버 시각입니다.** 학생 화면은 서버가 알려 주는 한국 시간(KST)으로 오늘 날짜와 지금 교시를 정합니다.
  - 학생 화면은 처음 열 때와 초기화 버튼을 누를 때 서버에서 시각을 받습니다(확정).
  - "지금 교시" 판단에 쓰는 시각의 정확도 목표는 03 NFR-009에 제안값으로 둡니다.
- **처음 열었을 때 기본값은 오늘 날짜와 지금 교시**입니다. 쉬는 시간에는 다음 교시를 기준으로 합니다. 지금이 수업 시간(1~9교시) 밖이면 교시를 직접 고르라고 안내합니다.
- **화면은 자동으로 바뀌지 않습니다.** 화면을 켜 둔 채 교시가 바뀌면, 학생이 초기화 버튼을 누릅니다.
- **지난 교시도 고를 수 있습니다.** 오늘 이미 지난 교시를 골라도 됩니다.
- **주말·공휴일은 운영하지 않습니다.**
  - 필터 달력에서 주말·공휴일 날짜는 흐리게 보이고, 누를 수 없습니다(고를 수 없음).
  - 단, 오늘이 주말·공휴일이면 기본 날짜는 오늘이 됩니다. 이때 캠퍼스맵(또는 건물 목록)에서 건물을 누르면 "운영하지 않는 날입니다" 같은 문구를 보여 줍니다.
  - 시간표 파일에 토요일·일요일 수업 줄이 있으면 저장하지 않고 경고로 알리는 방식을 제안합니다. **(제안값 — 사용자 확인 필요)**
- **공휴일 목록은 서버가 공공 공휴일 정보 API에서 받아 옵니다.** 달력 부품은 공휴일을 스스로 알지 못합니다. 그래서 서버가 공공 공휴일 정보 API(공공기관이 공휴일 정보를 내주는 창구)에서 공휴일을 받아 데이터베이스에 저장합니다.
  - 어떤 API를 쓸지는 `08_아키텍처_ADR.md`에서 정합니다. 무료이고 인증키 신청이 필요한 공공 API가 후보입니다.
  - 인증키는 관리자가 관리자 화면에서 입력하고 바꿉니다. 인증키는 서버에만 보관하고, 학생 화면·관리자 화면에 드러나지 않습니다. 보관 방법 세부는 `09_보안_개인정보.md`에서 정합니다.
  - 관리자가 관리자 화면에서 [공휴일 불러오기]를 누를 때 받아 옵니다(확정).
  - 받아 온 목록은 관리자가 확인한 뒤 저장합니다. 순서는 [공휴일 불러오기] → 받아 온 목록 보기 → 관리자가 [저장] → [공개하기]입니다(확정).
  - 받아 오기에 실패하면 관리자 화면에 실패 이유를 알리고, 이미 있는 목록은 그대로 둡니다.
  - 학교 휴업일과 API에 없는 휴일은 관리자가 관리자 화면에서 추가합니다. 저장한 목록도 관리자 화면에서 고칠 수 있습니다.
  - 저장한 공휴일 목록은 [공개하기]를 눌러야 학생 화면에 쓰입니다. 이때 기준 표시의 업데이트 시각도 바뀝니다(7.1-5).
  - 공휴일 목록을 데이터베이스에 어떤 칸으로 저장할지는 `06_데이터모델_ERD.md`에서 정합니다.
  - 목록에 없는 휴일은 운영하는 날로 보입니다. 관리자가 추가할 때까지 그렇습니다.
  - 서버는 학기를 반영할 때 공휴일 목록을 확인합니다. 반영하는 학기의 기간(시작일~종료일)이 걸친 연도의 공휴일이 없으면 관리자 화면에 경고합니다. 예: 2026-2학기(9~12월)라면 2026년 공휴일이 있는지 확인합니다. 학기가 두 해에 걸치면 두 해 모두 확인합니다. 경고 문구는 "2026년 공휴일 목록이 없습니다"처럼 빠진 연도를 알려 줍니다(확정).
  - 관리자 화면에서 공휴일을 저장할 때 서버가 날짜 형식을 검사합니다. 형식이 틀린 날짜는 저장하지 않고 관리자 화면에 알려 줍니다(확정).
  - 공휴일 목록이 비어 있으면, 달력에서 주말만 막고 학생 화면에는 따로 안내하지 않습니다. 빠진 공휴일은 서버의 경고로 관리자가 알아챕니다(확정).
  - 학생 화면이 공휴일 목록을 받지 못하는 경우는 따로 두지 않습니다. 다른 정보를 받지 못할 때와 같이 처리합니다(7.7).

### 7.7 실행 장소·관리자 화면 관련

- **실행 장소**: 학생 화면·관리자 화면·서버·데이터베이스를 모두 **관리자 PC(로컬 PC)**에서 실행해 시연합니다. 학생 대상 공개(서비스를 인터넷에 올려 누구나 접속하게 하는 것)는 하지 않습니다(3.2). 공공 공휴일 정보 API는 관리자 PC 밖에 있고, 서버가 인터넷으로 받아 옵니다(7.6).
- **관리 일은 모두 관리자 화면에서 합니다**(3.1 관리자 기능 표).
- **관리자 화면은 PC만 지원합니다.** 휴대폰 화면은 지원하지 않습니다(3.2).
- **관리자 로그인**: 관리자는 1명입니다. 관리자 화면에서 아이디·비밀번호로 로그인합니다. 비밀번호는 관리자 화면에서 바꿀 수 있습니다. 계정 추가·삭제와 역할 나누기는 없습니다.
  - 비밀번호는 8자 이상이고, 영문자·숫자·특수기호를 각각 하나 이상 포함해야 합니다(확정).
  - 로그인 화면과 문구는 실제 서비스 기준으로 만듭니다(확정).
  - 로그인 실패 시 잠시 막기, 자동 로그아웃, 문의·신고 보내기 한도 같은 보안 관련 시간·횟수는 서버 설정 파일에서 정합니다. 관리자 화면에서는 바꾸지 않습니다(확정).
  - 이것은 "관리할 수 있는 내용·설정 값은 관리자 기능으로 넘긴다"는 원칙의 예외입니다. 관리자 화면에 들어온 사람이 보안 설정을 낮추지 못하게 하기 위해서입니다.
  - 세부 숫자와 그 밖의 로그인 보안 규칙은 `03_기능명세서.md`·`09_보안_개인정보.md`에서 정합니다.
- **학생 화면에 보이는 때**: 학생 화면에 보이는 모든 변경(공지·배너·팝업, 공휴일 목록, 사용 불가 설정 포함)은 관리자 화면에서 저장한 뒤 [공개하기]를 눌러야 반영됩니다(확정).
  - 기준 표시의 업데이트 시각은 무엇을 공개했든 [공개하기]를 누른 시각입니다(7.1-5).
  - 저장한 내용과 공개한 내용을 어떻게 나눠 보관할지는 `06_데이터모델_ERD.md`·`08_아키텍처_ADR.md`에서 정합니다.
- **사용 불가 설정**: 공사나 갑작스러운 사정으로 건물·층·강의실을 쓸 수 없을 때, 관리자가 관리자 화면에서 설정합니다. 다른 변경과 같이 [공개하기]를 눌러야 학생 화면에 보입니다. 사용 불가로 설정된 강의실은 공실로 보이지 않습니다. 공실 판정 규칙(7.1 등) 자체는 바꾸지 않습니다.
  - 대상은 건물 전체, 층 하나, 강의실 하나 중에서 고릅니다(확정).
  - 기간은 시작일~종료일로 정합니다. 종료일을 비우면 관리자가 풀 때까지 유지합니다(확정).
  - 사유 문구(예: "공사 중")는 학생 화면에 보입니다(확정).
  - 사용 불가 기간에 든 날짜를 고르면, 해당 강의실은 공실로 보이지 않고 "사용 불가"로 보입니다. 층 하나가 사용 불가면 그 층의 강의실이 모두 "사용 불가"로 보입니다. 건물 전체가 사용 불가면, 건물을 누를 때 사유를 안내합니다(확정).
  - 학생 화면의 모양은 `04_화면설계서.md`·`05_UI디자인시스템_IA.md`에서 정합니다.
- **문의·신고는 사이트 안의 화면에서 받습니다.** 서버가 받은 내용을 데이터베이스에 저장합니다. 관리자는 관리자 화면의 목록에서 처리 상태를 관리합니다.
- **문의 이메일은 개인정보입니다.**
  - 1:1 문의의 이메일 칸은 **선택 사항**입니다. 적을 때는 **동의 체크**를 받습니다.
  - 이메일을 적지 않으면 답장을 받을 수 없다고 안내합니다.
  - 이메일은 데이터베이스에만 저장되고, 처리한 뒤 지웁니다. 보관 기간은 `09_보안_개인정보.md`에서 정합니다.
  - 신고 폼(내용을 적어 보내는 입력 양식)에는 이메일 칸이 없습니다. 신고에는 답장하지 않고 처리만 합니다.
- **문의 답장**: 관리자가 관리자 화면에서 답장을 쓰면, 서버가 학생이 적은 이메일로 메일을 보냅니다. 메일을 보내는 방식은 `08_아키텍처_ADR.md`에서 정합니다. 후보는 실제 메일 서비스와, 관리자 PC 안에서 보낸 메일을 받아 보여 주는 도구입니다.
- **방문 통계**: 서버가 일일 방문자 수와 건물 조회수를 직접 세어 데이터베이스에 저장합니다. 관리자는 관리자 화면의 대시보드에서 봅니다. 같은 브라우저는 하루에 1번만 셉니다. 서비스는 누구인지 저장하지 않으며, 누구인지 알 수 없는 숫자로만 봅니다. 식별값(2장) 안내·동의 여부는 `09_보안_개인정보.md`에서 정합니다.
- **학생 화면이 서버에서 정보를 받지 못할 때**: 학생 화면은 불러오기 실패 안내와 [다시 시도] 단추를 보여 줍니다(화면 모양은 `04_화면설계서.md`). 학생 화면에는 실패 이유를 보여 주지 않습니다.
- **오류 기록**: 서버는 처리하지 못한 일을 실패 이유와 함께 기록합니다. 예: 학생 화면의 요청 처리 실패, 공휴일 받아 오기 실패, 문의 답장 메일 보내기 실패. 관리자는 관리자 화면의 "오류 기록" 메뉴에서 기록 목록과 실패 이유를 봅니다. 이 메뉴는 대시보드와 따로 둡니다.
  - 대시보드에는 새 오류 건수만 보여 줍니다. 처리할 문의·신고 건수처럼, 누르면 오류 기록으로 이동합니다(확정).
  - 서버가 꺼져 있는 등 기록 자체를 남기지 못하는 경우를 어떻게 알아챌지는 `12_관측_로깅_감사.md`에서 정합니다.
- 신고하기의 신고 대상과 폼에 미리 채울 내용은 `03_기능명세서.md` FR-011에 제안값으로 적었습니다. 신고에는 답장하지 않습니다(확정).
- **학생 화면 안내 문구·신고 종류 선택지**: 관리자가 관리자 화면에서 고칩니다. 안내 문구의 처음 값은 지금 정해진 문구이고, 신고 종류 선택지의 처음 값은 `03_기능명세서.md` FR-011의 선택지입니다. 고친 내용은 [공개하기]를 눌러야 학생 화면에 보입니다.

### 7.8 기타 제약

- 학생 화면은 **PC 웹을 먼저** 만듭니다. PC 화면을 기준으로 설계하고, 휴대폰 브라우저에서도 깨지지 않게 합니다. 휴대폰 전용 화면·앱은 다음 단계에서 검토합니다. 관리자 화면은 PC만 지원합니다.
- 예상 사용자는 약 7,000명이고 동시 접속은 적을 것으로 봅니다.
- 학교 공식 앱과는 이번에 연동하지 않습니다.
- 기술스택(쓸 프로그램·도구)은 정하지 않았습니다. 프로그래밍 언어·데이터베이스 종류·서버 프레임워크·메일 보내는 방식·공공 공휴일 정보 API는 `08_아키텍처_ADR.md`에서 정합니다.
- **서비스가 저장하는 학생 정보는 문의 이메일뿐입니다.** 학생 로그인·알림·즐겨찾기가 없고, 위치 정보도 쓰지 않습니다. 문의 이메일은 선택 입력·동의로 받고, 처리 후 지웁니다(7.7).
